# Карта архитектуры AMSignal

C++17: CLI `lvm_reader` и нативный Win32 GUI используют общее ядро чтения
LVM/TXT/CSV и анализа сигналов. Ниже имена модулей означают пары `.cpp/.hpp`,
если расширение не указано. Начинай с заголовка нужного модуля и поиска символа.

## Поток данных и основные связи

### Бесплатная подпись Windows-выпусков (2026-10-14)

AM_version.rc задаёт Windows VERSIONINFO для GUI/CLI: ProductName AMSignal,
текстовая версия из git describe, одинаковые ProductVersion/FileVersion и
OriginalFilename. GUI включает его через AM_logo.rc; CLI получает отдельный
resource object. build_version_resource.ps1 генерирует ASCII RC с проверенными
значениями, избегая двойного quoting через PowerShell/windres/cpp. Windows Make
генерирует те же ресурсы; Linux CLI не требует Win32 resource compiler.

release-signpath.yml запускается вручную на main, принимает существующий
release tag из истории main, собирает/проверяет исходники на GitHub-hosted
Windows и передаёт ID неизменяемого upload-artifact в SignPath. Actions
закреплены по SHA; secret доступен только подписи, contents:write — только
созданию draft. SignPath Foundation требует ручного одобрения каждого запроса.
После возврата файлов verify_release_binaries.ps1 проверяет версии, Valid
Authenticode, издателя SignPath Foundation, timestamp и одинаковый сертификат
GUI/CLI. package_release.ps1 -InputDirectory ... -RequireSignature -Zip
копирует эти EXE, считает SHA256SUMS/asset .sha256 по итоговым байтам и создаёт
ZIP. Подписанные EXE не изменяются. Существующие каталоги, архивы и releases
не перезаписываются; результат GitHub — draft с EXE/ZIP/checksums.

Подключение бесплатного сервиса и сертификата ещё не одобрено. Pipeline нельзя
считать фактической подписью: нужны принятие Foundation, подключение GitHub App,
реальные SIGNPATH_* переменные/secret, MFA и человеческое approval. Политика и
честный pending-статус — docs/CODE_SIGNING.md, ссылки есть в трёх README;
docs/SIGNPATH_APPLICATION.md фиксирует отправку 2026-10-14 18:40 MSK с
разрешения владельца и подтверждение Form submitted. PR #1 применён после
успешного Windows/Linux CI; ответ ожидается на al.muleev@gmail.com. Принятие
проекта фондом, GitHub App/MFA и активация подписи ещё требуются.
docs/signpath-artifact.xml ограничивает подпись ровно двумя EXE AMSignal с
одинаковой версией. Подробности ресурсов и настройки не влияют на FFT/FRF.

Новая проверка tests/release_signing.ps1 даёт 25 условий: реальные метаданные
обоих EXE, отказ неподписанных при RequireSignature, неверной версии/пути,
неизменность существующего ZIP, наличие policy и точность SHA-256/ZIP-копий.
Обе штатные PowerShell-сборки прошли; локальный результат — dist/signpath-build.
Криптографическая успешная подпись/загрузка из сервиса требует его активации и
не имитируется самоподписанным сертификатом. Конкретные инструкции — в policy.

idle cache между submit_cached и началом расчёта не лишает Request входа.
cache_epoch независим от numerical_revision/job generation; clear_cache и
снижение RAM/disk квоты запрещают уже запущенной подготовке вернуть старый вход

неактивного документа. Два seed-отсчёта никогда не определяют этот Fs.

### Адаптивные ресурсы RAM/диска (2026-10-13)

Это актуальные правила; численные/загрузочные ограничения прошлых этапов ниже
описывают прежние версии. `resource_budget::resource_headroom` оставляет системе
20% min(available RAM, commit), минимум 512 MiB при достаточном свободном объёме,
иначе половину. Auto больше не ограничен 8 GiB или четвертью свободной памяти.
Manual 64…65536 MiB использует тот же безопасный headroom. Это admission для
крупных данных/расчётов, не жёсткий предел всей private memory (GDI/история отдельно).
При отказе GlobalMemoryStatusEx GUI использует консервативный headroom 128 MiB.

`gui_resources` задаёт AnalysisResources.memory_bytes из общего доступного
ledger, отмечая уже учтённые retained plans. 384 MiB — только default для
клиента API без состояния; явно заданные большие/малые допуски соблюдаются. FFT/FRF
используют RAM, когда оценка полного входа/подготовки/планов/результатов помещается;
иначе точный recording FFT переходит на диск, H1 — на потоковый источник. При
провале RAM admission/alloc временный кандидат удаляется до дискового повторения.
Auto/Direct и нехватка ресурсов никогда не уменьшают N или L автоматически.

`gui_loading::start_async_scan_task(path, adaptive_resident)` для файлов >512 MiB
выбирает discovery: ScanIndex, полный metadata-проход и допущенный RAM-кандидат
с оригинальными time/raw X/каналами. Вместе с временным ростом vector кандидат
занимает не более трети свободного допуска. Подходящий результат публикует полный
Dataset; неподходящий освобождается в том же проходе, публикуются source/seed.
Состав каналов проверяется по всей записи, source stamp перепроверяется. Обычный
resident loader также масштабирует свой допуск; потолка 2 GiB/правила 1/8 нет.
Полный filter Cadence нового adaptive RAM-документа сохраняется в immutable
RecordingSource.filter_sample_step; processed recipe учитывает этот Fs. Raw
GUI gap step по 4096 интервалам остаётся отдельным. Демоция сохраняет исходный
Fs фильтра, окно/анализ/разметку и numerical_revision, отменяя устаревшие задания.

`processor_resources.hpp` выбирает физические ядра, доступные процессу Windows
по affinity, с fallback к logical concurrency. Общий AnalysisExecutor лениво
расширяется, до 32 участников; Spectrum ограничивает число каналами и памятью,
FRF — Welch-сегментами, длиной L, размером tile и памятью. При занятом executor
вызывающий поток выполняет прежний последовательный путь. Tile накопления
сохраняет исходный порядок Sxx/Syy/Sxy. Малые задания остаются последовательными.

FrfWorker удерживает один подготовленный вход в пределах budget/3 RAM и
256 MiB disk. PreparedFrf и результаты удерживают свои RAII-резервы; удержание
кэшем — shared ownership того же входа, без отдельной копии. FrfSource.expected_samples
— точный N, не cap: допущенный вход из replay сразу пишется в RAM; несовпадение
N отклоняет результат. При неизвестном N/отказе допуска остаётся прежний диск.
OverviewWorker хранит четыре immutable view в min(128 MiB, budget/8); ключ включает
source object/recipe, диапазон, каналы, плотность, ширину, gap step и ограничения.
Перед повторной публикацией проверяется source stamp; cache hit не читает листья.
Уменьшение квоты запрещает завершившемуся старому заданию заново заполнить кэш.

`fft::trim_fft_cached_plans` освобождает idle планы всех потоков под registry mutex.
DFT держит pin на время использования; FLS/TLS cleanup остаётся прежнего типа,
registry переживает static teardown. GUI вытесняет idle кэши/неактивные результаты
и при исчерпании допуска переводит полные replayable документы на диск; активные
массивы отменённых заданий живут до фактического завершения. Частичные/нереплеируемые
документы сохраняются. Windows CLI вычисляет Auto-допуск после выбора данных,
избегает копии whole selection и освобождает ненужный original; загрузчик CLI
пока требует резидентный Dataset, это не новый потоковый CLI интерфейс.

### Вторая согласованная часть: обработка, дисковый FFT и экспорт

`gui_recording_processing::processed_recording_source` создаёт immutable
`RecordingSource::processed` поверх оригинала. Рецепт содержит полные формулы,
порядок каналов и настройки фильтра; источник проверяет stamp оригинала.
Replay владеет собственными FilterStream, переносит biquad-состояния между
блоками и прогревает их от начала записи до выбранного участка. Полный шаг
фильтра точно повторяет прежний файловый FRF через внешний Cadence (8 MiB),
лениво сохраняется в пределах рецепта; отменённая подготовка не сохраняет шаг.
Timeline-only replay не вычисляет формулы/фильтр. Бюджет блока делится на raw,
обработку и выходные буферы; невозможность вместить строку даёт ResourceLimit.
Нефинитные входы нелинейной формулы повторяют GUI transform_channel_value;
identity/affine сохраняют прежнюю арифметику и правила ошибок.

Обзор и Snap используют тот же обработанный источник, что source-FFT, FRF
и экспорт. Raw/affine показываются через исходный индекс с точным изменением
координат; CachedFormula и фильтр строят собственную иерархию по исходным
отсчётам. Не преобразовывай готовые min/max нелинейной формулой. Recipe входит
в ключ managed LRU и проверяемую identity AMSOIDX2; raw identity не изменена,
старые индексы перестраиваются однократно. В RAM удерживается только рецепт/шаг, а
обработанный обзор подчиняется общему дисковому LRU 2 GiB/256 элементов.
Фильтр при точном чтении/Snap участка может повторно читать префикс прогрева;
checkpoint состояний фильтра не сохраняется. Source-склейка использует
дисковую карту AMSOIDX2; исходные временные границы анализа не меняются.

`disk_spectrum::compute_recording_spectrum` выбирает RAM при допущенном точном
входе и численном scratch, иначе выполняет полный дисковый FFT.
`SpectrumWorker::submit_computation` сохраняет прежние заменяемый запрос,
отмену и generation; closures не читают g из потока. Источник удерживается
результатом и ещё раз проверяется в apply_spectrum_result перед публикацией.
Малый RAM FFT сохраняет общий analysis_executor; дисковый путь последователен
и не создаёт конкурирующий пул. Нехватка RAM при допуске ядра переводит на
диск только после уничтожения векторного входа и его резерва.

Дисковый radix-2 использует tiled bit reversal (128×128) и блоки 32768 комплексных
значений; короткие стадии выполняются в плитке, длинные — парой дисковых
блоков. W переносится между блоками без перезапуска рекурсии. Произвольный
N использует дисковый Bluestein с прежним chirp/знаками/нормировкой. Временная
ось сжимает разрывы и интерполирует линейно с прежними long double offset,
mean fill и удалением DC. N и сетка не сокращаются; отдельные FFT блоков не
усредняются. Численный допуск работы 24 MiB включает Cadence и плитки;
сохранённые RAM-планы также входят в численный максимум 384 MiB.

Scratch оценивается до создания больших массивов: для radix-2 56N байт,
для Bluestein 40N+48M, где M=nextpow2(2N-1), плюс амплитуды всех откликов.
Явный предел временного диска — 64 GiB и дополнительный запас свободного места
64 MiB. Системный temp используется первым; при нехватке места проверяется
каталог исходного файла. Ошибка записи/закрытия/отмена удаляют собственные
файлы RAII, без рекурсивного удаления постороннего содержимого. После успеха
удаляются вход, offsets и рабочие комплексные массивы; остаются только биновые
амплитуды и ограниченные summaries (до 2048 групп на канал). Их допуск живёт
в DiskSpectrum, не сбрасывается публикацией документа. Неактивные дисковые
результаты вместе ограничены 2 GiB, активный остаётся рабочим.

`Spectrum::bin_count/frequency/bin_range/read_amplitudes` — общий доступ к
результату: у дискового Spectrum resident freqs/amp пусты. GUI использует
`gui_disk_spectrum_render`, точные позиции extrema бинов и ограниченную
проекцию; приближение и FFT-Snap читают настоящие амплитуды. Сетка вычисляется
той же формулой. Чтение очень широкого приближения/FFT-Snap может занимать
время; FFT-Snap пока синхронный, его ошибка не публикует точку.

`gui_source_export` готовит в UI immutable recipe, метаданные и список каналов.
CSV/TXT/LVM/проект читают исходные отсчёты блоками, спектр — точные бины.
Проект сохраняет всю raw запись и обработку как настройки, включая разметку,
роли и область анализа; это переносимый полный файл, не ссылка на seed.
Интерактивный экспорт выполняется в отдельном I/O worker с owned ожиданием
и отменой; тяжёлый FFT экспорта использует тот же численный путь/исполнитель.
atomic_write_file заменяет назначение только после полного закрытия файла.
Активный source не перезаписывается; при сохранении поверх исходного проекта
потребуется другое имя. Это сохраняет неизменяемый источник открытого документа.
Отметка saved обновляется лишь для того же source/project_revision. Смена
документа и выход отменяют job; shutdown_source_exports вызывается до выхода

### Первый этап перехода к общему источнику записи

План и статус перехода: `docs/LARGE_RECORDINGS_PLAN.md`. Ниже исторические
шаги основания; текущий пользовательский сценарий и дисковый FFT описаны выше.

`analysis_range.hpp` задаёт `AnalysisRange::EntireRecording/Interval` и
`TimeRange`. Разрешение диапазона использует границы источника, а не viewport.
Выход за границы, обратный порядок и NaN/Inf отклоняются без изменения участка.
Обе границы включены; один момент времени допустим для чтения, минимальную
длину численного входа проверяет соответствующее ядро.

`recording_source` — общий API чтения без GUI и обработки. Файловый источник
владеет абсолютным путём, shared-индексом, соответствием логических каналов
физическим столбцам и отметкой размера/mtime. Индекс после передачи не изменяй.
У источника в RAM массивы передаются перемещением в неизменяемый Dataset,
без полной копии; вход должен уже иметь конечное упорядоченное время и
выровненные каналы. Размер файла не выдаётся за число отсчётов: файловый
источник пока не знает точный N из ScanIndex.

`RecordingReadRequest` задаёт независимый диапазон, порядок логических каналов,
максимум строк и бюджет буферов (по умолчанию 16 MiB). Пустой список каналов
читает только время. Блок ограничен 65536 строками и консервативной оценкой
16 байт на отсчёт каждого столбца, включая время и рост vector. Бюджет не
включает служебные строки парсера, индекс, обработку или память всего процесса.
Нулевые лимиты запрещены; невозможность вместить одну строку даёт ResourceLimit.
Каждый replay создаёт собственный reader и буферы, поэтому независимые запросы
могут читать один дескриптор одновременно. Callback получает заимствованные
массивы только на время вызова и не должен публиковать частичный результат.

Проверки отмены и версии файла выполняются до/после чтения и каждого блока.
Несовпадение индекса/ожидаемой отметки отклоняется при создании источника;
изменение или исчезновение файла после создания даёт SourceChanged.
Проверка размера/mtime не обнаруживает замену с сохранением обоих атрибутов.
Ошибки чтения, диапазона, отмены и ресурсов типизированы как RecordingFailure.

`gui_frf` передаёт общий источник в worker вместо собственного LoadOptions и
reader; прежние формулы, прогрев фильтра, проход Fs и отсечение прогрева
сохранены. SourceChanged/ResourceLimit передаются в соответствующие статусы FRF.

и Makefile; `tests/run_tests.exe --recording` запускает проверки источника.

### Источник документа и ресурсы загрузки — второй шаг

`DocumentState::recording_source` владеет общим файловым дескриптором, без
копирования Dataset. `apply_loaded_dataset` создаёт его и проверяет ожидаемый
size/mtime до `begin_loaded_document`; отказ сохраняет действующий документ.
Файловые документы получают источник при открытии; для прежнего пути и тестов
`gui_analysis_source::current_recording_source` создаёт его лениво и повторно
проверяет версию файла. Импорт спектра и временные Dataset без файла остаются
на прежнем векторном пути. Worker захватывает shared_ptr, который переживает
смену/закрытие документа. Значения формул/фильтров захватываются отдельно.

`resource_budget.hpp` задаёт проверяемую без Windows политику и MemoryBudget.
Auto: минимум 8 GiB и четверти суммы свободных RAM/commit и учтённых резидентных
массивов; свободный ресурс — минимум доступных RAM и commit. Manual:
64…65536 MiB. Оба режима ограничены суммой резидентных массивов и половины
свободного ресурса, сохраняя запас Windows и другим приложениям. RAII-резервы
не увеличивают оценку свободного ресурса. Если уже занятая память превышает
новый лимит, новые резервы запрещены; исходные данные не удаляются.

`gui_resources` учитывает capacity времени/raw_time/каналов, кэшей формул и
фильтра, результатов Spectrum/FRF, индексов MinMax и склейки всех документов.
Общие ScanIndex учитываются один раз по адресам; отсчёты не обходятся.
Это частичный учёт крупных массивов, а не точная память процесса: история,
строки/служебные структуры, GDI и временные массивы обработки ещё не подключены
к общему резервированию. Численные worker/FFT-планы подключены третьим шагом
ниже. Дополнительный численный бюджет 384 MiB сохраняется.

Перед загрузкой повторно снимаются ресурсы. Лимит парсера — минимум прежнего
Auto-предела и половины доступного резерва; в Manual вместо предела 1/8
используется максимум 2 GiB, но общий лимит и системный запас сохраняются.
Загрузка резервирует удвоенный лимит парсера для чтения и подготовки. Резерв
владеет ledger независимо от GUI; AsyncLoadResult объявляет его до Dataset,
чтобы массивы уничтожались первыми. Отмена не освобождает резерв до окончания
worker и удаления результата. При успешной публикации резерв освобождается
после передачи массивов документу, до следующего открытия в очереди. Неудачный
и устаревший результат также освобождается. ScanIndex передаётся reader только
при совпадении пути кэшированного сканирования. При отказе GlobalMemoryStatusEx
используется консервативная оценка свободного ресурса 1 GiB (Auto-участок не
более 128 MiB), без неограниченного режима.

Настройки «Данные: Auto» / `Data: Auto`, поле MiB и «Применить»
находятся в общем окне настроек. Enter применяет ручной лимит, Auto сохраняет
его для будущего возврата. INI `[resources] automatic/manual_mib`; недопустимое
сохранённое значение возвращает Auto/2048 MiB. Настройка глобальна для приложения,
не меняет numerical_revision, область анализа, L или методику. Показанный
эффективный бюджет пересчитывается при обновлении настроек; перед загрузкой
проверяется снова. 512 проверок ядра, включая 17 ресурсных; 477 GUI-проверок.

### Общий бюджет FFT/FRF — третий шаг

`analysis_resources.hpp::AnalysisResources` передаёт численный предел (не более
384 MiB), максимум участников (по умолчанию четыре) и общий MemoryBudget.
Перед построением снимка GUI резервирует вход; worker удерживает его до
уничтожения массивов. Ядро отдельно резервирует накопления, результаты,
рабочие массивы и планы. Крупные capacity документов и сохранённые планы
учитываются при обновлении ресурсов, кэш подготовленного входа — своим резервом.
Оценки консервативны и включают запас, это не измеритель всей памяти процесса.

Spectrum использует radix-2 непосредственно в рабочем комплексном массиве,
сохраняя dft/Bluestein для остальных длин. Входной N, удаление среднего,
сетка, обработка разрывов и нормировка прежние. Последовательный путь теперь
тоже проверяет ресурсы. При отказе N не уменьшается автоматически.

FRF выбирает число участников и плитку Welch из доступной памяти: до восьми
сегментов, до четырёх участников, с последовательным путём для малого объёма,
занятого исполнителя или недостаточного резерва для помощников. Если даже один
сегмент не помещается, возвращается ResourceLimit; Auto/Direct не меняют L.
Порядок накопления, общая FFT средней опоры, перекрытие и финализация прежние.
Потоковая подготовка резервирует 32 MiB плюс ограниченный блок чтения;
после освобождения временных массивов Reservation::shrink_to оставляет только
PreparedFrf::resident_bytes. Дисковый снимок не резервирует свою длину в RAM.

Резерв объявлен первым в Request/Spectrum/FrfBatchResult/PreparedFrf, чтобы
уничтожаться после данных. Прежний Request/result удаляется до присваивания
нового; cancel не освобождает активное владение. Публикация в документ
переводит массивы из резерва в учёт capacity. Кэш входа FRF освобождается при
смене его ключа, закрытии документа, новой загрузке и SourceChanged; активное
задание сохраняет собственный shared_ptr. Повтор с тем же ключом использует кэш.

Снижение лимита не удаляет исходные данные. Сохранённые планы других
простаивающих потоков пока не вытесняются автоматически и могут препятствовать
новому заданию при малом ручном лимите. История/GDI и временная обработка
полного сигнала остаются вне общего резервирования. Дисковый FFT теперь
подключён второй частью выше; следующие счётчики относятся к третьему шагу.

### Дисковая основа обзора — четвёртый шаг

`recording_overview` — отдельный API отображения, ещё не подключённый к GUI.
Численные входы, Dataset, фильтры и Snap не должны получать его агрегаты.
`RecordingOverview::build/open/open_or_build` принимает файловый RecordingSource
и явный путь кэша. По умолчанию нижний уровень содержит 1024 исходных строки
на узел, верхние уровни объединяют пары до корня. В памяти остаются рабочие
блоки и несколько узлов; уровни записываются и читаются на диске.

Каждый узел хранит исходный индекс/число строк, границы времени, максимальный
интервал и для каждого канала первые/последние конечные точки, min/max с их
исходными временем и индексом, число конечных значений. Равные экстремумы
сохраняют первую позицию. OverviewTrace::ordered_points возвращает точки
в порядке записи без повторов. Пропуски не превращаются в конечные значения;
OverviewBucket::discontinuous запрещает соединение через них или временной разрыв.
У отдельного нечислового отсчёта finite_count=0: view обозначает отсутствие
рисуемого значения, а различение NaN/Inf и численные измерения требуют
исходного чтения RecordingSource, не обращения к пустым полям экстремумов.

read_view выбирает уровни по ширине viewport/числу пикселей. Узлы принимаются
только целиком внутри участка; края и приближение читают настоящие отсчёты
через RecordingSource/ScanIndex. Результат ограничен памятью: чрезмерная
детализация даёт ResourceLimit, без частичного view или изменения участка.
Границы включены, пустой участок между отсчётами даёт пустой view.
visit_gaps отдельно потоково перечисляет все исходные интервалы больше
заданного порога в порядке записи. Порог определяется прежней методикой
вызывающей стороны, а не огибающей. Границы блоков/уровней не создают и
не скрывают разрывов; viewport целиком внутри разрыва сохраняет его границы.

Формат AMSOIDX2: 64 KiB заголовок, little endian/IEEE double, узел
48+104*C байт с FNV-1a контрольной суммой. Заголовок проверяет абсолютный
UTF-8 путь, размер/mtime и период часов файловой системы, границы и порядок
физических столбцов, размеры/смещения уровней и точную длину кэша. Узлы
проверяются при чтении; повреждение не публикует view. Источник проверяется
до/после операции и между блоками. Открытый handle сохраняет отдельный курсор
под mutex, параллельные запросы владеют собственными буферами. Лист дополнительно
хранит точные времена и якорь склейки с отдельной контрольной суммой; подробные
соседние листья читаются одним ограниченным исходным проходом до 65536 строк.

Пределы одного задания: подготовка 16 MiB, view 8 MiB, диск 512 MiB по
умолчанию; они явные и могут быть переданы вместе с общим MemoryBudget.
Резерв view сужается после завершения чтения до capacity результата и живёт
до его уничтожения; view не копируется, присваивание также сохраняет порядок
освобождения старых буферов/резерва. Source/ScanIndex учитываются владельцем отдельно.
Нехватка диска/ошибка записи/отмена/SourceChanged уничтожают частный scratch,
сохраняя прежний кэш до публикации. Завершённый индекс публикуется атомарной
заменой; отмена/изменение источника после неё не возвращает результат,
а уже полный кэш остаётся с проверяемой отметкой первоначальной версии.
Progress сообщает обработанные строки/байты в потоке построения; изменённый
в callback источник или отмена также проверяются. Исходный файл и symlink
не могут быть целью записи кэша. На Windows занятый старый handle может
мешать замене: менеджер GUI версионирует пути кэшей (восьмой шаг ниже).

### Фоновые задания обзора и документ — пятый шаг перехода

`overview_worker` выполняет build/open_or_build/read_view в одном фоновом потоке.
Он не участвует в FFT-пуле: это ввод/вывод, не независимый численный исполнитель.
Очередь содержит один заменяемый запрос. submit отменяет активный и удаляет
ожидающий запрос/неполученный результат; cancel не блокирует UI. shutdown
терминален, отменяет и соединяет поток; вызовы управления выполняет UI-поток.
Исходные массивы не копируются: request удерживает общий RecordingSource.

Request задаёт generation, источник, необязательный ранее открытый индекс,
путь кэша, бюджеты построения/view, участок, порядок каналов и ширину в пикселях.
Перед построением проверяются источник, участок/ширина и индексы каналов.
Готовый индекс должен принадлежать точно тому же объекту источника и укладываться
в max_disk_bytes. Прогресс построения заменяется безопасным snapshot: phase,
generation, rows, disk_bytes. Пользовательский build.progress не вызывается.
Отмена старого задания не может затереть прогресс или результат нового.
Result содержит полный immutable view/index и порядок каналов либо типизированную
ошибку, без частичных данных. OOM соответствует ResourceLimit.

`gui_overview` хранит index/view, каналы, generation, pending/error в
DocumentState::overview. Номер задания общий монотонный, независим от численной
ревизии. Публикация из UI проверяет generation и shared source, затем ещё раз
size/mtime: изменение файла после завершения worker тоже даёт SourceChanged.
При нём прежний обзор сбрасывается; остальные ошибки сохраняют прежний view.
Переключение/закрытие отменяет pending; завершённый view перемещается вместе
с документом без копирования buckets. View сохраняет собственный MemoryBudget
reserve до уничтожения последнего владельца, включая неактивный документ.
Не прибавляй эти же буферы к resident, пока существует reserve.
WM_TIMER(2) принимает результат; на выходе GUI worker явно shutdown после
message loop, до разрушения глобальных ресурсов. Никаких topmost окон он не создаёт.

Текущее подключение внутреннего рендера описано ниже; обычное открытие прежнее.
Dataset, обработка и FFT/FRF не получают огибающую. Нужны точные исходные
измерения, управление общим дисковым LRU и последующая замена Light Mode.
Слишком подробный view может превышать бюджет, даже если индекс уже построен.

### Рендер дискового обзора — шестой промежуточный шаг

`gui_overview_render` подключён к draw_time через внутренний флаг
DocumentState::overview.render_enabled (по умолчанию false, не сериализуется
и не имеет UI-переключателя). Обычное открытие включает его для файлового
обзора; у резидентного Dataset сохраняется прежний renderer.

`OverviewRequest::display_density` включает ограниченное уплотнение узлов и
оригинальных строк внутри ширины пикселя. Greedy-объединение соседних узлов
сохраняет точные min/max/первые/последние конечные координаты, finite_count,
максимальный исходный интервал и N. Текущий формат индекса — AMSOIDX2 (см. исправления выше).
Нижние узлы читаются исходными блоками; группы копятся без массива всех строк
и без выделения отдельного trace-вектора на каждый исходный отсчёт.
Эффективная pixel_columns ограничивается по стоимости bucket и бюджету,
затем сохраняется в view и переносится при move assignment. Это плотность
графика; N и L численных входов не меняются. Путь display_density=false
сохраняет прежние точные одиночные отсчёты и явный ResourceLimit.

`synchronize_overview_viewport` сравнивает участок, видимые каналы, ширину
(не более 8192) и политику ресурсов; одинаковый запрос не повторяется на paint.
Первое построение индекса завершается, даже если пользователь меняет viewport;
после него новый view читается из индекса. Приготовленный view с другим участком
не рисуется как текущий: до публикации показывается ожидание внутри графика.
Смена Auto/manual повторяет запрос с новым admission, оформление — нет.

Соединение разрешено только для полностью конечных узлов без интервала выше
порога и безопасной границы между ними. Смешанные узлы показывают отдельные
конечные точки, включая оба экстремума; NaN/Inf не превращаются в значения.
Порог — cached_global_gap_step*64 вызывающей стороны, не разность времён
агрегатов. Полный исходный шаг и карточки разрывов подготавливает worker
нового открытия. Fs/обработка разрывов численного ядра не менялись.

Identity сохраняет значения, включая signed zero. Affine использует прежние
mul/add и арифметику; отрицательный mul разворачивает экстремумы для авто-Y.
Нелинейные формулы, фильтр и склейка явно дают неподдерживаемый preview,
без подстановки raw. Переполнение преобразованных extrema/диапазона не
переходит в координаты GDI. Сглаживание действует только на оригинальные
одиночные отсчёты, не на агрегаты. Используются общие оси/легенда/разметка/PNG,
в обеих темах. Выделение общего участка показывается отдельной подложкой.

Буферы view сохраняют RAII-reserve; GDI и ограниченный буфер визуального сплайна
относятся к прежней неполной модели памяти процесса. Dataset/численные входы
не меняются. Внутренний preview блокирует старый синхронный Snap по Dataset;
асинхронное исходное чтение добавлено ниже. Исходные CSV/проекты пока не
переведены на потоковый source-путь: source-документ явно блокирует их,
чтобы не экспортировать seed-отсчёты как всю запись.

Рабочий бюджет дополнительно учитывает группы/кандидаты выбранных trace,

### Исходный Snap — седьмой промежуточный шаг

`RecordingOverview::nearest_sample(RecordingSnapRequest)` ищет конечный
исходный отсчёт по экранному расстоянию во всём запрошенном участке.
Индекс задаёт только нижнюю оценку расстояния до прямоугольника время/min/max;
оценка имеет наружные границы и запас округления, поэтому неподходящие узлы
можно безопасно исключить. Приоритет обхода следует времени курсора; результат
при равенстве расстояний задаётся порядком запрошенных каналов и ранней строкой,
а не порядком обхода дерева. Исходные кандидаты читаются RecordingSource из
листьев блоками; включённые границы участка проверяются для каждой строки.
Поддержаны identity и affine с прежними mul/add. Нечисловые raw/processed
значения пропускаются; переполнение extrema расширяет оценку, не отбрасывает
конечные значения внутри листа. Огибающая не используется как кандидат.

Рабочий бюджет по умолчанию 2 MiB: консервативный стек обхода, selected channels
и parser buffers допускаются через общий MemoryBudget. На выходе возвращаются
только исходные time/value/channel/sample и счётчики прочитанных листьев/строк,
резерв снимается после уничтожения буферов. В худшем случае поиск может читать
все листья участка. Без ScanIndex каждое исходное чтение может повторно читать
префикс файла; сохранение индекса доступа добавлено восьмым шагом ниже.

`overview_worker` исполняет исходный поиск в том же единственном I/O-потоке.
Добавлены независимые заменяемые SnapRequest/SnapResult: submit_snap отменяет
прежний Snap, не view; cancel отменяет view, cancel_snap — Snap, shutdown — оба.
Ожидающий Snap имеет приоритет перед следующим view, но не прерывает текущее
чтение view. Полных частичных результатов нет; ошибки типизированы, отменённый
запрос не публикуется. Никакого дополнительного FFT-пула не создаётся.

`gui_overview_snap` захватывает источник, отдельный generation, numerical/project
revision, viewport/оси/размер, видимость каналов, выбранный инструмент, Snap,
блокировку и политику ресурсов. WM_TIMER(2) проверяет их и size/mtime заново
перед UI-callback. SourceChanged удаляет устаревший view/index. Новая навигация,
клик/задание, Escape, смена/закрытие документа и Undo/Redo отменяют старый Snap;
одного сравнения project revision недостаточно при цикле Undo/Redo.

`gui_input` откладывает создание точки/маркера/направляющей до исходного чтения.
Перенос сохраняет прежние координаты до отпускания и успешного поиска;
результат создаёт одно обычное Undo-действие, Redo хранит уже найденные координаты.
Ошибка, отсутствие конечных кандидатов и отмена не создают неснятый с сигнала
fallback и не меняют разметку. Состояние чтения/ошибка показываются внутри графика,
без глобального окна ожидания. Прежний синхронный Snap по Dataset в preview
возвращает false; его нельзя использовать вместо асинхронной операции.

### Дисковый LRU и сохранение ScanIndex — восьмой промежуточный шаг

`disk_cache` владеет частным каталогом исходных индексов. Общий предел по
умолчанию 2 GiB/256 элементов включает ScanIndex, обзоры и максимальные
квоты незавершённых выходов. begin_write допускает квоту до построения и
проверяет свободный диск, commit после закрытия файла сужает её до реальных

`PreparedFrf` хранит векторный либо дисковый вход с единым доступом по отсчётам.
`compute_prepared_frf` читает плитки последовательных сегментов (до восьми,
обычно до 16 MiB), сохраняет перекрытие Welch через общие позиции отсчётов
и никогда не усредняет готовые H1/coherence блоков. FFT опоры общая для всех
откликов. Рабочие FFT степеней двойки выполняются in-place, остальные —
прежним DFT/Bluestein. Среднее не суммируется при отключённом удалении.
Проверка компонент комплексных чисел сохраняет проверку `abs` для значений
больше `DBL_MAX/2`, поэтому конечные компоненты с переполнением модуля
остаются ошибкой. Накопления long double идут строго в порядке сегментов;
финализация H1, coherence, порога слабой опоры и спектра выполняется однажды.

`analysis_executor.hpp` заменяет частный пул Spectrum общим исполнителем:
до четырёх участников, один пакет одновременно, исключения передаются после
завершения всех помощников. FRF выбирает параллельный путь при >= 7 сегментах
и L >= 256, снижает число участников по CPU/бюджету. Малые задачи, занятый
исполнитель и недостаточный бюджет многопоточности выполняются последовательно.
В бюджете 384 MiB считаются фактические сохранённые планы всех потоков,
возможные новые планы/рабочие массивы, FFT, накопления и результаты;
бюджет не ограничивает весь процесс. Если даже один сегмент не помещается,
возвращается `ResourceLimit`; Auto и Direct не меняют методику или длину L.
Для длинного H1 пользователь задаёт допустимое L явно.

на диске. Более крупный снимок удаляется после задания, поэтому повторный
расчёт такого входа повторяет чтение/подготовку. Generation отвечает только
за выдачу результатов; ключ входа включает источник/размер/время изменения,
численную ревизию документа, точные границы, роли, raw/processed и обработку.

ключ. Файл, изменённый после загрузки или во время чтения, даёт `SourceChanged`
и требует открытия заново.

ревизию; имена обновляет `refresh_frf_channel_names` без нового задания.

изменения до чтения и перед приёмом Dataset и сохраняет исходную отметку файла.

`main.cpp` (CLI) или `gui_loading` → `lvm_parser` + `data_io` → `lvm::Dataset`.
Dataset содержит время, исходное время, каналы и метаданные. Парсер также
распознаёт сохранённые спектры; нормализация времени и удаление дубликатов
временных колонок учитывают тип данных. `generated_names` отличает имена,
назначенные парсером для пустых или осевых заголовков, от имён из файла:
после удаления повторов времени только назначенные имена `Channel_N`
перенумеровываются по оставшимся каналам.

GUI хранит активный документ и представление в общем `gui::App` (`gui_state`, экземпляр `g`).
`App` наследует `DocumentState`, поэтому существующие обращения `g.ds` остаются
обращениями к активному источнику; `gui_documents` хранит неактивные
`DocumentState` и переключает их через move/swap, не дублируя большие массивы
`Dataset`. В документ входят каналы, обработка, видимый/выделенный участок,
режим Time/FFT/FRF и их кэши; окна, настройки и единственная очередь загрузки
остаются общими для приложения.
`gui_processing` применяет формулы/фильтры и управляет их кэшами;
`gui_render_data` даёт значения и диапазоны для `gui_render`.
`gui_analysis_source` выбирает общий временной участок и создаёт снимки каналов.
`gui_spectrum` передаёт снимок → `spectrum_worker` →
`analysis` → `fft`; результат принимается с учётом поколения запроса.
`fft` выполняет radix-2 с проверками отмены между блоками не более 16384
butterfly вне арифметического цикла; рекуррентный twiddle сохраняется между
блоками одного FFT-блока. Bluestein переиспользует один завершённый
chirp/FFT-kernel план на поток, до 64 MiB; смена N освобождает старый план,
отмена не публикует недостроенный, большие планы живут только в текущем вызове.
Исходная длина DFT, частотная сетка и арифметические формулы не меняются.
`analysis` использует общий с FRF ленивый исполнитель для независимых каналов при
N >= 65536: до четырёх участников, включая вызывающий поток, и не больше
числа каналов/логических процессоров. Один канал, короткая запись или занятый
пул используют последовательный путь. Планировщик снижает число участников
по оценке рабочих массивов и новых планов плюс фактическим сохранённым планам в бюджете
384 MiB; входные данные, общий временной массив и прочая память приложения
не входят в этот бюджет. Это оценка для выбора параллелизма, а не жёсткий
лимит процесса. Задачи пишут в отдельные слоты; все заканчиваются до возврата,
после чего результат и исключения собираются в исходном порядке каналов.
Новых потоков на каждое вычисление нет; отмена использует прежний флаг ядра.
Выход из GUI явно завершает `SpectrumWorker::shutdown()` (отмена + join)
перед разрушением общего пула; обычный `cancel()` не завершает worker.
В GUI worker применяет аффинные формулы каналов к уже выделенному участку;
сложные формулы и фильтр
пока готовятся до задания, поскольку фильтр зависит от границ полного сигнала.
`gui_frf` выбирает каналы и передаёт небольшой `FrfBatchInput` либо владеющий
источником `FrfSource` → `frf_worker` → `frf_stream` →
`frf_analysis::compute_prepared_frf`: арифметическое среднее
Reference по отсчётам → общая подготовка `FrfSamples` → один проход по Welch
сегментам для нескольких Response → модуль `fft`, функция `lvm::dft`.
Окно, подготовка/FFT опоры и Sxx считаются один раз на сегмент; у каждого
Response отдельные Syy/Sxy и последующая финализация комплексного H1/coherence.
Порог слабого входа, частоты и амплитудный спектр опоры общие, но выходные
массивы принадлежат отдельным результатам для совместимости API. FFT всех
сегментов не сохраняются; дополнительная память накоплений — O(R * L),
а не O(K * L). Один Response использует тот же подготовленный пакетный путь;
публичный `compute_frf` сохранён как совместимый одиночный estimator.
`FrfBatchResult` хранит отдельный результат каждого Response; ошибка одного
Response не скрывает остальные. API одиночной пары `analyze_frf` сохранён.
Численное ядро принимает подготовленные массивы и общий равномерный шаг;
оно не зависит от Dataset или индексов каналов GUI. Результат FRF хранит
комплексный H1, coherence и отдельные маски допустимости вне Spectrum.
`gui_export` использует данные/обработку/спектр и `data_io` для записи файлов;
`gui_export_metadata` сериализует настройки и аннотации в комментарии и
восстанавливает их при загрузке через `gui_loading`. Метаданные не зависят
от подготовки отсчётов, PNG и диалогов сохранения.

## Где менять поведение

Пользовательские X/Y всех режимов рисует общая `gui_render::draw_user_axis_names`
без заливки фона: Y — в строке над всей областью графика (в FRF также над
полосой Ч/Б-легенды), X — справа на общей строке с физической подписью,
сразу под числовыми делениями X. Пользовательская X занимает не больше трети
ширины, физическая подпись центрируется в оставшемся поле с отступом;
оба текста ограничены своими полями. `gui_layout::plot_rect` и `gui_export::save_png` резервируют
эти поля через `kAxisNameTop`, `kAxisNameXOffset` и `kAxisBottom`; инвалидация
графика и FRF-навигации включает верхнее поле. Общий осевой шрифт, цвет темы
и `DT_END_ELLIPSIS` обеспечивают одинаковое оформление и ограничение длинных
названий выделенными полями без перекрытия данных. `user_axis_names_outside_plot`
проверяет пиксели во всех режимах/темах и при узком графике; GUI-набор также
создаёт PNG с длинными названиями и FRF со скрытой опорой для проверки вида.
Оформление осей и управление легендой выпущены вместе в v0.16.10;
двуязычная запись находится в CHANGELOG. После исправления компоновки X,
высоты легенды и крайних частот FRF GUI-набор содержит 398 проверок;
`frf_long_edge_ticks.png` служит визуальной проверкой длинной крайней частоты.
Исправления компоновки описаны в CHANGELOG v0.16.11; нижнее поле окна и PNG
уменьшено до 44 пикселей, общая строка подписей X начинается через 22 пикселя.

Легенда Signal/Spectrum (`gui_render::draw_legend`) управляется документным
`show_channel_legend`: крестик (`gui_input`) и пункт «Вид → Легенда каналов»
(`gui_menu`, `gui_commands`) вызывают одну команду `IDM_CHANNEL_LEGEND`.
Скрытие сразу очищает строки и области кликов, сохраняя видимость каналов.
Крестик размещён в отдельной правой колонке первой строки: высота легенды
остаётся равна высоте списка каналов с прежними полями; области каналов
не включают колонку крестика. `gui_frf_render` измеряет числовые подписи X
и сдвигает их внутрь ширины графика у границ для линейной и логарифмической
частоты; фиксированные прямоугольники, выходившие за край, не используются.
Флаг входит в `SettingsSnapshot`/Undo/Redo и графические метаданные проекта
(`gui_export_metadata`); у новых файлов и старых проектов легенда включена.
PNG использует ту же отрисовку и учитывает скрытие. FRF не имеет этой
накладной легенды, поэтому пункт меню там недоступен; полоса Ч/Б-кривых
остаётся отдельной. Регрессия `channel_legend_visibility` проверяет команду,
крестик, очистку областей, историю и независимость документов; экспортный
набор проверяет восстановление флага из проекта.

Терминология интерфейса согласована через `gui_text`, меню, подсказки и FRF:
`Auto scale`, `Spectrum (FFT)` / `Спектр (БПФ)`, `Filter family` / `Семейство фильтра`,
`ФНЧ`/`ФВЧ`, общая формула каналов и `Reference channels`. Верхняя ось FRF —
`FRF magnitude |H|` / `АЧХ |H|`: единицы отношения зависят от входа/выхода,
поэтому безразмерность не утверждается автоматически. Русские показания FRF
локализуют Гц, перекрытие, прямой метод и когерентность.
`gui_render::point_difference_text` используется обоими графиками FRF и Time/FFT:
обратная разность времени имеет единицу Гц, частоты — секунды, при равных X — `—`;
нижний график использует `ΔA` с единицами амплитуды. `d (условн.)` / `d (coord.)`
сохраняет числовое расстояние координат без физического смысла или единиц.
Временной режим в кнопке, меню, статусе, подсказках и настройках осей назван
«Сигнал» / `Signal`; физическая временная ось и заголовки экспорта остаются
«Время» / `Time`. Внутренний `AnalysisMode::Time` не переименовывается.
Визуальный сплайн назван «Сглаживание каналов» / `Channel smoothing`
отдельно от октавного сглаживания FRF.
`gui_layout` размещает списки режима и семейства фильтра справа от подписей
в общей колонке; ширина подписей учитывает язык, семейство не занимает две строки.
Регрессия `measurement_label_units` проверяет обратные разности времени/частоты,
совпадающие X, отдельные единицы амплитуды опоры и русскую подпись секунд;
изменения интерфейса этого набора описаны в CHANGELOG v0.16.8.

Верхняя панель (`gui_layout`, `gui_window`) разделена на источник/режимы и
инструменты/вид; Автомасштаб расположен над Панелью у правого края. «Курсор» снимает режимы добавления разметки; «Линия» открывает
выбор вертикальной/горизонтальной линии через `gui_commands`, используя прежние
команды и горячие клавиши. Подписи Signal/Spectrum/FRF берутся из отдельных
компактных локализованных строк `gui_text`, а форматные строки статуса с параметрами
используются только нижней строкой. Воспроизведение сигнала и сброс вида находятся в «Вид».
`gui_side_panel` сохраняет скрытыми прежние кнопки воспроизведения, сброса и линий
после возврата со стартового экрана. Селектор показывает только имя файла.

## Ограничения, которые важно сохранять

- FFT использует доступные отсчёты всего выбранного участка, сжимая пропуски.
  Явный лимит отсчётов может сократить выборку; неточные метки времени требуют
  интерполяции. `sampling.hpp` используется также экранной склейкой.
- Экранная склейка не изменяет исходное время Dataset и экспорта. Готовый
  спектр открывается без повторного FFT и временной обработки амплитуд.
- FRF использует непустые непересекающиеся списки Reference и Response одного
  Dataset с общим участком; видимость каналов не влияет на выбор. Выделение
  приоритетно, иначе берётся видимый временной диапазон. Обработка по умолчанию
  включена для согласованности с Time/FFT и может быть явно отключена для расчёта
  по исходным каналам. При включении она применяется к каждому каналу
  до арифметического среднего Reference. Среднее вычисляется во времени до
  Welch/H1; каждый Response рассчитывается относительно этого общего сигнала
  с одинаковыми Fs, L, K, overlap и частотной сеткой. Это не MIMO.
  У нового или загруженного документа списки ролей пусты. Каждый контроль роли открывает
  единый меню-подобный Win32-popup первого варианта с системными флажками в светлой
  теме и с палитрой приложения в тёмной:
  изменение флажка сразу применяет выбор, но не закрывает popup; он закрывается
  кликом вне меню или повторным нажатием того же контрола. Остальные контроли
  правой панели при выборе не скрываются. Границы окна слегка скруглены. Имена выбранных каналов выводятся на
  контроле, пока помещаются, иначе показывается их число; для нескольких
  опор дополнительно выводится `AVG of N channels`. Компактный пункт `Clear`
  внизу очищает только открытую роль и не закрывает popup. Канал противоположной
  роли отображается недоступным, поэтому пересечение ролей невозможно.
- FRF рассматривает выбранные отсчёты как единую последовательность с
  t[n]=n/Fs. Fs определяется из типичного положительного шага timestamps
  через `sampling.hpp`, а не из общей длительности участка. Значения и число
  samples сохраняются точно: нет вставки нулей, удаления или интерполяции.
  Разрывы (dt > 1.5 * typical_dt) только устанавливают `gaps_ignored` для
  предупреждения в статусе и CSV. Welch-окна могут пересекать gaps и границы
  LVM sections. Экранная настройка склейки не влияет на FRF и его кэш.
  NaN/Inf, несогласованные каналы и некорректное время по-прежнему отклоняются.
- Основной метод — H1/Welch: среднее удаляется в каждом сегменте, окно Hann
  периодическое, nfft=L, шаг L/2. Накапливаются |X|², |Y|² и conj(X)*Y;
  H1=sum(conj(X)*Y)/sum(|X|²). Общий множитель нормировки PSD и 1/K сокращаются.
  Auto выбирает степень двойки порядка N/4 без ограничений по gaps;
  явное L — чётное число >=4. Панель и CSV показывают фактические L, K, Fs/L
  и overlap. Проверка длины сравнивает L с общим числом выбранных samples;
  неполный хвост не дополняется нулями. Direct использует один FFT всей выборки.
- Coherence вычисляется из тех же накопителей: |Sxy|²/(Sxx*Syy). При K<2,
  слабом входе или нулевой мощности выхода она недоступна; допустимость H
  и coherence разделена. Coherence остаётся диагностическим значением и не
  изменяет кривую КД. Комплексный transfer сохранён для будущей Phase.
- В FRF DC исключён, а слабый вход маскируется по суммарной мощности Sxx:
  порог равен max(Sxx)*(1e-6)², плюс численный порог.
  Маска разрывает кривую. Истинный нулевой отклик сохраняется и показывается
  как КД 0. КД строго равен abs(H): это отношение амплитуды Response к
  амплитуде арифметически усреднённого Reference, без перевода в dB.
  Автоматическая вертикальная шкала КД всегда начинается с нуля; вертикальное
  масштабирование не смещает эту базовую линию.
- Рядом с H1/Direct вычисляется односторонний линейный спектр средней опоры:
  `2*sqrt(mean(|X|²))/sum(Hann)`. Он выводится отдельным нижним графиком на той же
  частотной сетке и никогда не смешивается с безразмерной шкалой КД. Это также
  позволяет видеть действие фильтра, которое может сократиться в отношении H,
  если одинаково применено к Reference и Response. Шкалы согласованы: для
  линейной системы `амплитуда Response = КД × амплитуда средней Reference` на
  одном частотном бине. Цифровой фильтр имеет спад,
  поэтому компоненты за частотой среза ослабляются, а не удаляются из сетки.
- FRF хранит согласованные физические и log10(Hz) границы частотного вида,
  отдельные границы КД и готовый результат. В панели можно переключать
  логарифмическую и линейную ось без нового расчёта. Среднюю опору можно
  скрыть, изменить её высоту перетаскиванием разделителя с видимым захватом
  из трёх коротких серых полосок и курсором вертикального изменения размера
  (вплоть до почти равной высоты графиков) и её собственную
  вертикальную шкалу — Ctrl+колесом над этим графиком; Ctrl+колесо, Alt+колесо
  и вертикальное перетаскивание меняют её верхнюю Y-границу с нулевой базой,
  как у КД и Spectrum. Перетаскивание также панорамирует общую с КД частотную
  шкалу X. Автомасштаб возвращает автоматические Y-диапазоны обоих графиков.
  Coherence — диагностическая величина и не меняет допустимые бины или вид
  кривой. На графике доступно сглаживание по логарифмической полосе от выключенного до 1/3 октавы;
  оно не меняет комплексный H или CSV/метаданные. Масштабирование и панорамирование
  инвалидируют только график и подписи осей, не перерисовывая правую панель или
  строку состояния. Изменения вида не запускают расчёт. Участок, списки каналов, метод/L, применяемая обработка и
  загрузка файла инвалидируют кэш; устаревшие поколения результата игнорируются.
  В FRF применяются общие с Time/FFT режимы маркеров, вертикальных/горизонтальных
  линий и измерительных точек: точки на нижнем графике средней опоры привязаны
  к его физической шкале амплитуды, сохраняются отдельными от точек КД группами
  и при Snap выбирают ближайший допустимый частотный бин опоры; выбранный маркер или тип линии остаётся активным
  после каждого клика во всех трёх режимах, а `Esc` и «Курсор» его отключают;
  в режиме «Курсор» клик по существующей точке, маркеру или линии запускает
  перенос с одним действием Undo/Redo; Snap при переносе сохраняется. Snap
  вертикальной и горизонтальной направляющей берёт
  соответственно X или Y ближайшей отображаемой кривой; для АЧХ это кривая с
  активным сглаживанием. Кнопка `🔒` в верхней панели блокирует добавление,
  перенос и очистку разметки активного документа, но не навигацию графика.
  Щелчок по объекту дополнительно выделяет его; `Delete` удаляет выделенную
  точку, маркер или направляющую одним действием истории. Маркер всегда рисует
  точку в своей позиции, вертикаль X и горизонталь Y через неё. При совпадении
  маркера с вертикальной направляющей их подписи разводятся по разные стороны
  линии; у левого края подпись маркера сдвигается вправо за значением линии.
  Активные инструменты создания имеют приоритет над существующей разметкой,
  поэтому объекты можно поставить в той же позиции; в режиме «Курсор» клик
  выбирает объект, а перенос начинается сразу при тяге. ПКМ не выполняет
  массовую очистку разметки. Для Точек, Маркера и Линии короткий клик создаёт
  объект, а тяга после нажатия минимум на 4 пикселя панорамирует график.
  Дубликаты не создаются: точка уникальна в своей группе, маркер — в текущем
  режиме по X/Y, направляющая — по режиму, направлению и значению.
  После удаления последней точки группа немедленно удаляется из состояния и
  списка групп; её восстановление вместе с точкой входит в то же Undo/Redo.
  Проверки этого пути должны сверять отсутствие/восстановление группы, а не
  обращаться к её прежнему индексу после удаления.
  Обычные `Delete` и `Backspace` всегда обрабатываются графиком как удаление
  выделенного объекта; старые пользовательские назначения очистки точек не
  создают для них accelerator. В Time разметка над визуальной областью разрыва
  проверяется раньше карточки разрыва, поэтому её можно захватить и перенести.
  Любой клик по графику возвращает фокус главному окну, чтобы клавиши удаления
  не оставались у ранее использованного дочернего контрола.
  вертикальная координата маркера/линии хранится в
  Hz, горизонтальная и точка — в КД. Для FRF выделены свои группы точек и
  маркеры, но доступны те же настройки, очистка и Undo/Redo. При включённом
  Snap измерительная точка выбирает ближайший отображаемый бин КД — с
  настройкой сглаживания, применённой к отрисованной кривой, и в координатах
  активной линейной или логарифмической частотной шкалы. В FRF вверху
  правой панели расположены кнопки `Каналы`, `Точки` и `Фильтр`. Первая показывает
  параметры расчёта и выбор ролей, вторая — настройки измерительных точек,
  третья — общий фильтр всех каналов текущего документа с обычной прокруткой.
  Панель расчёта начинается ниже кнопок и видна только на вкладке «Каналы».
  Отдельные кнопки Calculate/CSV/PNG в панели не создаются: Enter в L
  сохраняет внутреннюю команду расчёта, экспорт использует общие команды;
  подсказка следует сразу за применением частотного диапазона.
  Регрессии вкладок (`frf_filter_tab`) и расчёта по Enter входят в набор
  из 353 GUI-проверок; изменения панели и названий описаны в CHANGELOG v0.16.9.
  Переход в FRF сохраняет вкладку фильтра; его изменение использует общий путь
  обработки и пересчитывает FRF при включённом `Apply channel processing`.
  Верхняя панель программы не дублирует кнопку точек.
- CSV FRF содержит частоту, `dynamic_coefficient`, Re/Im, valid, coherence,
  coherence_valid, `reference_amplitude` и reference_valid,
  а также метод и фактические параметры расчёта. Coherence доступна под курсором.
  Несколько Response отображаются вместе с цветами каналов и легендой
  `Response / AVG(Reference...)`; Auto Y учитывает все кривые. CSV для нескольких
  Response добавляет `response_index,response_name` перед прежними колонками;
  одиночный Response сохраняет прежний префикс численных колонок. Метаданные
  перечисляют выбранные Reference/Response и способ усреднения, помечают КД как
  `linear_abs_h`, а амплитуду опоры как `linear_one_sided`. PNG содержит оба графика.
  Общий CSV-экспорт в режиме FRF направляется в этот формат, LVM недоступен.
  Маркер `data_kind=frf` предотвращает ошибочное открытие как временного сигнала;
  обратный импорт FRF пока не реализован. PNG использует общий `draw_chart`.
  Отображение Phase и H2 оставлены для следующих этапов.
- Переключатель `Вид → Фигуры кривых для Ч/Б` добавляет графикам повторяемые
  комбинации штрихов и фигур (круг, квадрат, треугольник, ромб, кресты). Он
  действует на Time, FFT, FRF и PNG, сохраняется в проекте и входит в Undo/Redo.
  Для нескольких FRF-кривых соответствия выводятся в отдельной полосе над
  графиком, а не поверх данных.
- FFT видимых каналов выполняется в фоне. Скрытие/возврат каналов текущего кэша
  и простой возврат на вкладку FFT не требуют пересчёта; новый канал, участок
  или обработка — требуют. `spectrum_matches_current_source` сравнивает кэш с
  текущим участком до запуска worker'а.
- Диалог открытия поддерживает выбор нескольких файлов, а drag-and-drop — все
  переданные пути. Файлы грузятся последовательно единственным worker'ом; каждый
  успешный результат становится отдельным документом. Переключение отменяет
  незавершённые FFT/FRF задания и игнорирует их устаревшие результаты, но
  сохраняет готовые кэши в пределах бюджета, выделение, каналы и параметры
  анализа каждого файла.
  Верхний селектор рядом с кнопкой открытия показывает имя активного источника:
  из него можно сразу перейти к любому файлу, а соседняя
  кнопка закрывает текущий. «Файл → Открытые файлы» остаётся запасным способом;
  при закрытии активируется другой документ, если он есть.
- Если в текущем режиме ещё нет групп точек, переключатели отображаемых величин
  задают `g.pdisp` как шаблон для первой группы; после её создания настройка
  остаётся индивидуальной для активной группы.
- Режим точек включён по умолчанию во всех трёх режимах. Короткий клик создаёт
  точку, а смещение курсора минимум на 4 пикселя после нажатия запускает
  панорамирование; при выключенном режиме точек постановка не выполняется.
- Реализации GUI компилируются отдельно, `.cpp` не включаются друг в друга.
  Подключай профильный заголовок: `gui_settings_hotkeys.hpp` содержит только
  редактор сочетаний, `gui_export_metadata.hpp` — только API метаданных.
  Новые `gui_*.cpp` автоматически входят в Makefile и `build_gui.ps1`.
  Приложение и GUI-тесты используют те же объектные файлы. Заголовки
  самодостаточны, определения глобальных объектов находятся в одном `.cpp`.
  Новые оконные сообщения проходят через `gui_main` в профильный обработчик.
- Undo/Redo хранит изменения настроек и измерений; изменения обработки должны
  согласованно обновлять кэши и историю. Изменяемое состояние пока общее в App.

## Проверки и служебные файлы

- После любых изменений актуализируй эту карту и `AGENTS.md` вместе.

- Git: заголовок коммита — только английский, подробное тело коммита —
  только русское. Описание релизного тега должно быть максимально подробным
  и приведено на русском и английском.

- `tests/run_tests.cpp`: чтение, формулы, FFT/пропуски, диапазоны, min/max,
  импорт спектра, сохранность записи, FRF (усиление, фаза, пороги, ошибки,
  H1 с известной фазой, статистика выходного шума/coherence, синхронность,
  инвариантность H1/coherence к gaps, L больше отдельной LVM section,
  недостаточная длина выборки и фоновые задания; арифметическое среднее Reference,
  его линейный спектр, несколько комплексных Response, совместимость одиночной
  пары, частичные ошибки).
  Запуск из корня: `make test`.
  После пересборки тестового EXE только FRF: `tests/run_tests.exe --frf`.
- `tests/gui_regression.cpp`: экспорт/повторное открытие, автоматический обзор, фоновые
  FFT, FRF/логарифмическая навигация/CSV/PNG/панель, нулевая база КД, отдельная
  амплитуда средней опоры, фильтрация и Ч/Б-фигуры, постоянные инструменты
  маркеров/линий, множественный выбор и легенда,
  обработка перед средним Reference, постоянное меню ролей, `Clear`, пустые
  роли после загрузки, склейка, история и сообщения окна.
  Windows: добавь `-Test` к команде
  сборки GUI ниже или используй `make test-gui`. Проверяет логику, не вид окон.
  Обе GUI-цели Makefile линкуются с `uxtheme`, необходимой для тематического
  FRF popup.
- `tests/recording_overview_tests.cpp` входит в общую сборку `make test`;
  после пересборки `tests/run_tests.exe --overview` проверяет только дисковый
  индекс, точные view/разрывы, ресурсы, кэш, отмену и инвалидацию источника.
- `tests/recording_cache_tests.cpp` входит в `make test`; после пересборки
  `tests/run_tests.exe --cache` проверяет только дисковый LRU, lease/квоты,
  AMSCIDX1, отмену/повреждение/сохранность источника и managed overview.
- `tests/perf_benchmark.cpp`: ручной воспроизводимый профиль, не входящий в CI.
  По умолчанию он измеряет синтетические uniform signals (`262144` samples,
  `3` FFT channels, `2` References и `4` FRF Responses): FFT, пакетный H1/FRF
  и построение/запрос `MinMaxIndex`; `--input <path>` отдельно измеряет парсинг
  реального LVM/TXT/CSV. Запуск штатного профиля из корня: `make bench`.
  Для сравнимых результатов фиксируй CPU, режим питания, размер/число каналов,
  аргументы `--samples`, `--responses`, `--repeats` и медиану запусков.
- Полная сборка обоих приложений: команды ниже либо `make all gui` на Windows.
  Скрипты рассчитаны на передачу аргументов через Windows PowerShell;
  запускай их через `powershell.exe`, в том числе из PowerShell 7.

  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_cli.ps1
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_gui.ps1
  ```

- CI: `.github/workflows/build.yml` — ядро на Linux, оба набора и обе программы

- Выпуск: обновить CHANGELOG, создать коммит и аннотированный тег с русским
  и английским описаниями, затем выполнить обе штатные сборки из чистого
  помеченного коммита. Проверить `git describe` и версию CLI; GUI должен называться
  `AMSignal-<версия>-x64.exe`. `package_release.ps1 -OutputDir <новый каталог
  внутри dist> -Zip` включает GUI, CLI, запускатели, README и GPLv3 LICENSE.
  В GitHub отправляются ветка и конкретный новый тег; старые теги не заменяются.
