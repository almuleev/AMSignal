# Карта архитектуры AMSignal

AMSignal — C++17: CLI `lvm_reader` и нативный Win32 GUI используют общее ядро
LVM/TXT/CSV, обработки, FFT и FRF. Имена модулей ниже означают `.cpp/.hpp`,
если расширение не указано. Начинай с владельца поведения и его заголовка.

## Поток данных

```text
CLI main / GUI gui_loading
  -> lvm_parser + data_io -> Dataset / RecordingSource
  -> gui_documents -> активный DocumentState в App
  -> Signal: gui_processing / gui_recording_processing
             -> gui_render_data / gui_overview -> gui_render
  -> общий участок: gui_analysis_source
     -> FFT: gui_spectrum -> spectrum_worker -> analysis / disk_spectrum -> fft
     -> FRF: gui_frf -> frf_worker -> frf_stream -> frf_analysis -> fft
  -> gui_export + gui_export_metadata -> data_io / общий draw_chart для PNG
```

`Dataset` — данные; `RecordingSource` — независимое чтение исходника;
`DocumentState` — состояние конкретного документа; `App` — активный документ
и общие окна/настройки/worker. Неактивные документы перемещаются без копирования
больших Dataset. Численное ядро не зависит от Win32 и глобального GUI-состояния.

Обзор min/max обслуживает отображение, а FFT/FRF и точный Snap читают исходные
отсчёты. Резидентный и дисковый пути должны сохранять численный смысл и полный
выбранный участок. Нехватка RAM не разрешает молча уменьшать N, L или число каналов.

## Границы ответственности

- `gui_main` маршрутизирует сообщения в профильные обработчики; не переносить
  туда расчёт, сериализацию и геометрию панели.
- `gui_layout` владеет геометрией/видимостью прокручиваемых контролов;
  `gui_side_panel` и профильные панели синхронизируют состояние.
- `gui_commands` проводит пользовательские изменения через штатные команды,
  согласуя историю, ревизии и инвалидацию. Прямая подмена флага в тесте может
  пропустить необходимую инвалидацию и не воспроизвести реальную команду.
- Worker владеет входом задания; поколения и версия источника защищают от
  применения устаревшего результата. Отмена и shutdown имеют разный смысл.
- Viewport, оформление, численный участок и разметка — разные виды состояния.
  Не запускай расчёт и не меняй численную ревизию из-за простого изменения вида.
- Экспорт проекта сохраняет исходные данные и настройки; экспорт обработанных
  каналов применяет обработку. PNG использует общую отрисовку.

Перед правкой прочитай только нужный раздел [контрактов](development/CONTRACTS.md):
там правила RAM/диска, H1/Welch, фильтра, отмены, Undo и ввода.

## Сопровождение карты

Тексты страниц GitHub Releases находятся в `docs/releases/*-github.md`:
краткое резюме и скачивание отделены от раскрываемого полного журнала.
Название страницы соответствует тегу версии; статус задаётся полями GitHub Release.
Поставка готовой программы — GUI EXE; SHA256SUMS.txt описывает доступные вложения.
Архивы Source code формируются GitHub из тега и содержат исходники для сборки.
Исходные журналы версий сохраняются рядом в `docs/releases/`.

Добавляй новый модуль/владельца в `development/MODULES.md`, изменение поведения —
в соответствующий контракт, новую команду сборки — в `development/TESTING.md`.
Не добавляй сюда журналы прогонов, даты каждой локальной правки и списки релизов.
Подробности прежней карты сохранены в истории; при расхождении с реализацией
установи актуальное поведение по коду и тестам, затем исправь нужный справочник.
