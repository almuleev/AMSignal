# Карта архитектуры AMSignal

C++17: CLI `lvm_reader` и нативный Win32 GUI используют общее ядро чтения
LVM/TXT/CSV и анализа сигналов. Ниже имена модулей означают пары `.cpp/.hpp`,
если расширение не указано. Начинай с заголовка нужного модуля и поиска символа.

## Поток данных и основные связи

`main.cpp` (CLI) или `gui_loading` → `lvm_parser` + `data_io` → `lvm::Dataset`.
Dataset содержит время, исходное время, каналы и метаданные. Парсер также
распознаёт сохранённые спектры; нормализация времени и удаление дубликатов
временных колонок учитывают тип данных.

GUI хранит активный документ и представление в общем `gui::App` (`gui_state`, экземпляр `g`).
`App` наследует `DocumentState`, поэтому существующие обращения `g.ds` остаются
обращениями к активному источнику; `gui_documents` хранит неактивные
`DocumentState` и переключает их через move/swap, не дублируя большие массивы
`Dataset`. В документ входят каналы, обработка, видимый/выделенный участок,
режим Time/FFT/FRF и их кэши; окна, настройки и единственная очередь загрузки
остаются общими для приложения.
`gui_processing` применяет формулы/фильтры и управляет их кэшами;
`gui_render_data` даёт значения и диапазоны для `gui_render`.
`gui_analysis_source` выбирает общий временной участок и создаёт снимки каналов.
`gui_spectrum` передаёт снимок → `spectrum_worker` →
`analysis` → `fft`; результат принимается с учётом поколения запроса. Для GUI worker
применяет аффинные формулы каналов к уже выделенному участку; сложные формулы и фильтр
пока готовятся до задания, поскольку фильтр зависит от границ полного сигнала.
`gui_frf` выбирает каналы и передаёт массивы `FrfBatchInput` (time/references/responses)
→ `frf_worker` → `frf_analysis::analyze_frf_batch`: арифметическое среднее
Reference по отсчётам → общая подготовка `FrfSamples` → прежний `compute_frf`
для каждого Response → модуль `fft`, функция `lvm::dft`.
`FrfBatchResult` хранит отдельный результат каждого Response; ошибка одного
Response не скрывает остальные. API одиночной пары `analyze_frf` сохранён.
Численное ядро принимает подготовленные массивы и общий равномерный шаг;
оно не зависит от Dataset или индексов каналов GUI. Результат FRF хранит
комплексный H1, coherence и отдельные маски допустимости вне Spectrum.
`gui_export` использует данные/обработку/спектр и `data_io` для записи файлов;
`gui_export_metadata` сериализует настройки и аннотации в комментарии и
восстанавливает их при загрузке через `gui_loading`. Метаданные не зависят
от подготовки отсчётов, PNG и диалогов сохранения.

## Где менять поведение

Верхняя панель (`gui_layout`, `gui_window`) разделена на источник/режимы и
инструменты/вид; Автомасштаб расположен над Панелью у правого края. «Курсор» снимает режимы добавления разметки; «Линия» открывает
выбор вертикальной/горизонтальной линии через `gui_commands`, используя прежние
команды и горячие клавиши. Подписи Time/Spectrum/FRF берутся из отдельных
компактных локализованных строк `gui_text`, а форматные строки статуса с параметрами
используются только нижней строкой. Воспроизведение сигнала и сброс вида находятся в «Вид».
`gui_side_panel` сохраняет скрытыми прежние кнопки воспроизведения, сброса и линий
после возврата со стартового экрана. Селектор показывает только имя файла.

## Ограничения, которые важно сохранять

- FFT использует доступные отсчёты всего выбранного участка, сжимая пропуски.
  Явный лимит отсчётов может сократить выборку; неточные метки времени требуют
  интерполяции. `sampling.hpp` используется также экранной склейкой.
- Экранная склейка не изменяет исходное время Dataset и экспорта. Готовый
  спектр открывается без повторного FFT и временной обработки амплитуд.
- FRF использует непустые непересекающиеся списки Reference и Response одного
  Dataset с общим участком; видимость каналов не влияет на выбор. Выделение
  приоритетно, иначе берётся видимый временной диапазон. Обработка по умолчанию
  включена для согласованности с Time/FFT и может быть явно отключена для расчёта
  по исходным каналам. При включении она применяется к каждому каналу
  до арифметического среднего Reference. Среднее вычисляется во времени до
  Welch/H1; каждый Response рассчитывается относительно этого общего сигнала
  с одинаковыми Fs, L, K, overlap и частотной сеткой. Это не MIMO.
  У нового или загруженного документа списки ролей пусты. Каждый контроль роли открывает
  единый меню-подобный Win32-popup первого варианта с системными флажками в светлой
  теме и с палитрой приложения в тёмной:
  изменение флажка сразу применяет выбор, но не закрывает popup; он закрывается
  кликом вне меню или повторным нажатием того же контрола. Остальные контроли
  правой панели при выборе не скрываются. Границы окна слегка скруглены. Имена выбранных каналов выводятся на
  контроле, пока помещаются, иначе показывается их число; для нескольких
  опор дополнительно выводится `AVG of N channels`. Компактный пункт `Clear`
  внизу очищает только открытую роль и не закрывает popup. Канал противоположной
  роли отображается недоступным, поэтому пересечение ролей невозможно.
- FRF рассматривает выбранные отсчёты как единую последовательность с
  t[n]=n/Fs. Fs определяется из типичного положительного шага timestamps
  через `sampling.hpp`, а не из общей длительности участка. Значения и число
  samples сохраняются точно: нет вставки нулей, удаления или интерполяции.
  Разрывы (dt > 1.5 * typical_dt) только устанавливают `gaps_ignored` для
  предупреждения в статусе и CSV. Welch-окна могут пересекать gaps и границы
  LVM sections. Экранная настройка склейки не влияет на FRF и его кэш.
  NaN/Inf, несогласованные каналы и некорректное время по-прежнему отклоняются.
- Основной метод — H1/Welch: среднее удаляется в каждом сегменте, окно Hann
  периодическое, nfft=L, шаг L/2. Накапливаются |X|², |Y|² и conj(X)*Y;
  H1=sum(conj(X)*Y)/sum(|X|²). Общий множитель нормировки PSD и 1/K сокращаются.
  Auto выбирает степень двойки порядка N/4 без ограничений по gaps;
  явное L — чётное число >=4. Панель и CSV показывают фактические L, K, Fs/L
  и overlap. Проверка длины сравнивает L с общим числом выбранных samples;
  неполный хвост не дополняется нулями. Direct использует один FFT всей выборки.
- Coherence вычисляется из тех же накопителей: |Sxy|²/(Sxx*Syy). При K<2,
  слабом входе или нулевой мощности выхода она недоступна; допустимость H
  и coherence разделена. Coherence остаётся диагностическим значением и не
  изменяет кривую КД. Комплексный transfer сохранён для будущей Phase.
- В FRF DC исключён, а слабый вход маскируется по суммарной мощности Sxx:
  порог равен max(Sxx)*(1e-6)², плюс численный порог.
  Маска разрывает кривую. Истинный нулевой отклик сохраняется и показывается
  как КД 0. КД строго равен abs(H): это отношение амплитуды Response к
  амплитуде арифметически усреднённого Reference, без перевода в dB.
  Автоматическая вертикальная шкала КД всегда начинается с нуля; вертикальное
  масштабирование не смещает эту базовую линию.
- Рядом с H1/Direct вычисляется односторонний линейный спектр средней опоры:
  `2*sqrt(mean(|X|²))/sum(Hann)`. Он выводится отдельным нижним графиком на той же
  частотной сетке и никогда не смешивается с безразмерной шкалой КД. Это также
  позволяет видеть действие фильтра, которое может сократиться в отношении H,
  если одинаково применено к Reference и Response. Шкалы согласованы: для
  линейной системы `амплитуда Response = КД × амплитуда средней Reference` на
  одном частотном бине. Цифровой фильтр имеет спад,
  поэтому компоненты за частотой среза ослабляются, а не удаляются из сетки.
- FRF хранит согласованные физические и log10(Hz) границы частотного вида,
  отдельные границы КД и готовый результат. В панели можно переключать
  логарифмическую и линейную ось без нового расчёта. Среднюю опору можно
  скрыть, изменить её высоту перетаскиванием разделителя с видимым захватом
  из трёх коротких серых полосок и курсором вертикального изменения размера
  (вплоть до почти равной высоты графиков) и её собственную
  вертикальную шкалу — Ctrl+колесом над этим графиком.
  Coherence — диагностическая величина и не меняет допустимые бины или вид
  кривой. На графике доступно сглаживание по логарифмической полосе от выключенного до 1/3 октавы;
  оно не меняет комплексный H или CSV/метаданные. Масштабирование и панорамирование
  инвалидируют только график и подписи осей, не перерисовывая правую панель или
  строку состояния. Изменения вида не запускают расчёт. Участок, списки каналов, метод/L, применяемая обработка и
  загрузка файла инвалидируют кэш; устаревшие поколения результата игнорируются.
  В FRF применяются общие с Time/FFT режимы маркеров, вертикальных/горизонтальных
  линий и измерительных точек: точки на нижнем графике средней опоры привязаны
  к его физической шкале амплитуды, сохраняются отдельными от точек КД группами
  и при Snap выбирают ближайший допустимый частотный бин опоры; выбранный маркер или тип линии остаётся активным
  после каждого клика во всех трёх режимах, а `Esc` и «Курсор» его отключают;
  клик по существующей точке, маркеру или линии имеет приоритет над созданием
  новой разметки и запускает перенос с одним действием Undo/Redo; Snap при
  переносе сохраняется. Кнопка `🔒` в верхней панели блокирует добавление,
  перенос и очистку разметки активного документа, но не навигацию графика.
  вертикальная координата маркера/линии хранится в
  Hz, горизонтальная и точка — в КД. Для FRF выделены свои группы точек и
  маркеры, но доступны те же настройки, очистка и Undo/Redo. При включённом
  Snap измерительная точка выбирает ближайший отображаемый бин КД — с
  настройкой сглаживания, применённой к отрисованной кривой. В FRF вверху
  правой панели расположены кнопки `Каналы` и `Точки`; панель расчёта начинается
  ниже них. Первая показывает параметры расчёта и выбор ролей, вторая — настройки измерительных точек.
  Верхняя панель программы не дублирует кнопку точек.
- CSV FRF содержит частоту, `dynamic_coefficient`, Re/Im, valid, coherence,
  coherence_valid, `reference_amplitude` и reference_valid,
  а также метод и фактические параметры расчёта. Coherence доступна под курсором.
  Несколько Response отображаются вместе с цветами каналов и легендой
  `Response / AVG(Reference...)`; Auto Y учитывает все кривые. CSV для нескольких
  Response добавляет `response_index,response_name` перед прежними колонками;
  одиночный Response сохраняет прежний префикс численных колонок. Метаданные
  перечисляют выбранные Reference/Response и способ усреднения, помечают КД как
  `linear_abs_h`, а амплитуду опоры как `linear_one_sided`. PNG содержит оба графика.
  Общий CSV-экспорт в режиме FRF направляется в этот формат, LVM недоступен.
  Маркер `data_kind=frf` предотвращает ошибочное открытие как временного сигнала;
  обратный импорт FRF пока не реализован. PNG использует общий `draw_chart`.
  Отображение Phase и H2 оставлены для следующих этапов.
- Переключатель `Вид → Фигуры кривых для Ч/Б` добавляет графикам повторяемые
  комбинации штрихов и фигур (круг, квадрат, треугольник, ромб, кресты). Он
  действует на Time, FFT, FRF и PNG, сохраняется в проекте и входит в Undo/Redo.
  Для нескольких FRF-кривых соответствия выводятся в отдельной полосе над
  графиком, а не поверх данных.
- В Light Mode FFT выполняется в фоне. Скрытие/возврат каналов текущего кэша
  и простой возврат на вкладку FFT не требуют пересчёта; новый канал, участок
  или обработка — требуют. `spectrum_matches_current_source` сравнивает кэш с
  текущим участком до запуска worker'а.
- Диалог открытия поддерживает выбор нескольких файлов, а drag-and-drop — все
  переданные пути. Файлы грузятся последовательно единственным worker'ом; каждый
  успешный результат становится отдельным документом. Переключение отменяет
  незавершённые FFT/FRF задания и игнорирует их устаревшие результаты, но
  сохраняет готовые кэши, выделение, каналы и параметры анализа каждого файла.
  Верхний селектор рядом с кнопкой открытия показывает имя активного источника:
  из него можно сразу перейти к любому файлу, а соседняя
  кнопка закрывает текущий. «Файл → Открытые файлы» остаётся запасным способом;
  при закрытии активируется другой документ, если он есть.
- Если в текущем режиме ещё нет групп точек, переключатели отображаемых величин
  задают `g.pdisp` как шаблон для первой группы; после её создания настройка
  остаётся индивидуальной для активной группы.
- Режим точек включён по умолчанию во всех трёх режимах. Короткий клик создаёт
  точку, а смещение курсора минимум на 4 пикселя после нажатия запускает
  панорамирование; при выключенном режиме точек постановка не выполняется.
- Реализации GUI компилируются отдельно, `.cpp` не включаются друг в друга.
  Подключай профильный заголовок: `gui_settings_hotkeys.hpp` содержит только
  редактор сочетаний, `gui_export_metadata.hpp` — только API метаданных.
  Новые `gui_*.cpp` автоматически входят в Makefile и `build_gui.ps1`.
  Приложение и GUI-тесты используют те же объектные файлы. Заголовки
  самодостаточны, определения глобальных объектов находятся в одном `.cpp`.
  Новые оконные сообщения проходят через `gui_main` в профильный обработчик.
- Undo/Redo хранит изменения настроек и измерений; изменения обработки должны
  согласованно обновлять кэши и историю. Изменяемое состояние пока общее в App.

## Проверки и служебные файлы

- После любых изменений актуализируй эту карту и `AGENTS.md` вместе.

- Git: заголовок коммита — только английский, подробное тело коммита —
  только русское. Описание релизного тега должно быть максимально подробным
  и приведено на русском и английском.

- `tests/run_tests.cpp`: чтение, формулы, FFT/пропуски, диапазоны, min/max,
  импорт спектра, сохранность записи, FRF (усиление, фаза, пороги, ошибки,
  H1 с известной фазой, статистика выходного шума/coherence, синхронность,
  инвариантность H1/coherence к gaps, L больше отдельной LVM section,
  недостаточная длина выборки и фоновые задания; арифметическое среднее Reference,
  его линейный спектр, несколько комплексных Response, совместимость одиночной
  пары, частичные ошибки).
  Запуск из корня: `make test`.
  После пересборки тестового EXE только FRF: `tests/run_tests.exe --frf`.
- `tests/gui_regression.cpp`: экспорт/повторное открытие, Light Mode, фоновые
  FFT, FRF/логарифмическая навигация/CSV/PNG/панель, нулевая база КД, отдельная
  амплитуда средней опоры, фильтрация и Ч/Б-фигуры, постоянные инструменты
  маркеров/линий, множественный выбор и легенда,
  обработка перед средним Reference, постоянное меню ролей, `Clear`, пустые
  роли после загрузки, склейка, история и сообщения окна.
  Windows: добавь `-Test` к команде
  сборки GUI ниже или используй `make test-gui`. Проверяет логику, не вид окон.
  Обе GUI-цели Makefile линкуются с `uxtheme`, необходимой для тематического
  FRF popup.
- `tests/perf_benchmark.cpp`: ручной воспроизводимый профиль, не входящий в CI.
  По умолчанию он измеряет синтетические uniform signals (`262144` samples,
  `3` FFT channels, `2` References и `4` FRF Responses): FFT, пакетный H1/FRF
  и построение/запрос `MinMaxIndex`; `--input <path>` отдельно измеряет парсинг
  реального LVM/TXT/CSV. Запуск штатного профиля из корня: `make bench`.
  Для сравнимых результатов фиксируй CPU, режим питания, размер/число каналов,
  аргументы `--samples`, `--responses`, `--repeats` и медиану запусков.
- Полная сборка обоих приложений: команды ниже либо `make all gui` на Windows.
  Скрипты рассчитаны на передачу аргументов через Windows PowerShell;
  запускай их через `powershell.exe`, в том числе из PowerShell 7.

  ```powershell
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_cli.ps1
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_gui.ps1
  ```

- CI: `.github/workflows/build.yml` — ядро на Linux, оба набора и обе программы
  на Windows при push/pull request.
- `lvm_files_for_tests/test.lvm` — постоянный тестовый пример. `tests/_tmp_*`,
  тестовые EXE, `.build/` и объектные файлы — воспроизводимые результаты.
  Прямой запуск EXE не пересобирает тест; GUI-тест оставляет временный экспорт.
- `docs/archive/` — необязательные локальные отчёты, исключённые из Git;
  их отсутствие нормально. История опубликованных изменений — `CHANGELOG.md`.
  `docs/assets/` — изображения README; `AMS.ini` — локальные настройки.
