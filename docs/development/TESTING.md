## Выбор минимального набора

Проверяй завершённую серию связанных правок. Для смешанной задачи объединяй
необходимые проверки без повторов; расширяй набор при новой ошибке или
неопределённых границах влияния. Не запускай проверки после каждого сохранения.

| Изменения | Перед завершением |
| --- | --- |
| Только документация, комментарии, правила | Просмотр diff и `git diff --check`; без сборок/тестов |
| Только тесты | Пересборка тестового EXE и затронутый набор; без отдельных сборок приложений |
| Только GUI | GUI-сборка и затронутые GUI-проверки; без CLI |
| Только CLI | CLI-сборка и проверки затронутого поведения; без GUI |
| Общее ядро, общие заголовки/интерфейсы | CLI и GUI, затронутые core и GUI-интеграции |
| Сборочные скрипты, ресурсы, упаковка | Затронутые цели/артефакты; общие настройки — обе программы |
| Релиз/тег или широкое изменение с неопределённым влиянием | Обе сборки и полные core/GUI; для релиза также версия и пакет |

Успешная проверка сохраняет силу, пока не изменились влияющие на неё исходники,
зависимости или условия запуска. Правка документации или смена dirty-маркировки
не требует повторного прогона. Повтор — для диагностики нестабильности или по
прямому запросу пользователя. Невозможность нужной проверки объясни в ответе.

Сборки выполняются из корня репозитория через Windows PowerShell `powershell.exe`
или GNU Make. GUI использует инкрементальные общие объекты приложения/тестов.
Не отключай предупреждения или тесты ради успешного результата.

## Команды

```powershell
# CLI
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_cli.ps1
# GUI (без запуска тестов)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_gui.ps1
# GUI-тесты: пересборка и один запуск полного GUI-набора
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_gui.ps1 -Test
# Если пользовательский GUI запущен и блокирует EXE
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./build_gui.ps1 -OutputDirectory dist/<имя-задачи>
```

GNU Make: `make all` — CLI, `make gui` — GUI, `make test` — core,
`make test-gui` — GUI-регрессия. Эти тестовые цели сами запускают набор:
не запускай затем тот же EXE ещё раз без причины.

Для выбранной core-группы сначала `make tests/run_tests.exe` на Windows
(`make tests/run_tests` на Linux), затем EXE с одним из селекторов ниже.
Если Make отсутствует, используй ту же команду компиляции из цели тестов
в Makefile; не исполняй заведомо старый EXE. Не нужен новый сборочный скрипт
или диагностический стенд ради разовой проверки.

| Селектор `tests/run_tests.exe` | Область |
| --- | --- |
| `--frf` | FRF, несколько откликов, потоковый вход/фильтрация |
| `--recording` | Источник записи и индексированное чтение |
| `--overview` | Обзор, view, разрывы, точный Snap |
| `--cache` | Дисковый LRU, lease, квоты и повреждение |
| `--resources` | Политика бюджета памяти |
| `--analysis-resources` | Резервирование ресурсов FFT/FRF |
| `--disk-fft` | Дисковый FFT |
| `--adaptive` | Адаптивный выбор пути анализа |
| `--edge` | Крайние случаи ресурсов/отмены |
| без аргументов | Весь набор ядра |

Актуальный состав селекторов — `main` в `tests/run_tests.cpp`. Если селектора
нужной области нет, запускай соответствующий набор целиком; не создавай
систему отбора ради одной задачи. Общая тестовая инфраструктура требует всего
затронутого набора. GUI пока имеет общий регрессионный запуск; специальный
`--source-opening PATH` используй только для задачи открытия указанного файла.
Дополнительный `--opening-only` завершает этот сценарий после подготовки полного
обзора, с отдельным новым кэшем приложения, без последующего полного FFT/FRF.
Бюджет данных сценария — 64 MiB; это проверка дискового пути, а не режима Auto.

## Качество и стоимость проверок

- Нужен проверяемый результат: правильные значения, состояние, ошибка,
  инвалидация, пиксели или геометрия. Один успешный `save_png` подтверждает
  экспорт, но не отсутствие обрезанного текста.
- Выбирай данные, достигающие нужной ветви алгоритма. Большой N оправдан
  порогом/внешней сортировкой, а не повторением той же арифметики во всех вариантах.
- Не сравнивай число assertions с числом самостоятельных сценариев. Попарная
  уникальность/геометрия может дать тысячи утверждений при малом времени.
- Длинные логи сохраняй в `.build/`; читай итог и ошибки, при сбое — участок
  с причиной. Не повторяй успешные прогоны только ради нового счётчика.
- CI `.github/workflows/build.yml`: Linux — core и CLI, Windows — оба набора
  и обе программы при push/pull request. Локальный отбор не сокращает CI.

## Производительность и артефакты

`tests/perf_benchmark.cpp` / `make bench` — ручная диагностика, не порог CI.
Реальный файл: `tests/perf_benchmark.exe --input <путь>`. Фиксируй версию/чистоту
исходников, размер/хэш входа, CPU, питание, бюджет, N/L/каналы и число повторов.
Одиночное наблюдение не называй медианой или доказанной общей регрессией.
Не возобновляй исторические незавершённые замеры без запроса. Приоритет размера
испытаний — до 10 GB, как задано в AGENTS.md.

`--stream-input` измеряет ограниченное потоковое чтение вместо удержания всего
файла в RAM; `--parse-participants 1` выбирает последовательное преобразование
чисел (без параметра — Auto). `--frf-direct` выбирает Direct вместо H1.
Хэши входных значений и численных результатов помогают сравнить варианты;
при сравнении сохраняй одинаковые N, L, каналы и режим чтения. Время разбора
в стенде не равно полному времени открытия GUI с построением обзора.

`tests/_tmp_*`, тестовые EXE и `.build/` — воспроизводимые артефакты;
`AMS.ini` — локальные настройки; `docs/archive/` — необязательный игнорируемый
архив. Не опирайся на их наличие как на обязательную часть checkout.
Исторические протоколы, которые нужно сохранить в Git, находятся отдельно
в `docs/development/history/`.

## Выпуск

- Заголовок коммита — английский, подробное тело — русское; аннотированный
  релизный тег содержит полный RU/EN журнал. CHANGELOG и release notes согласованы.
- Чистый помеченный checkout, обе штатные сборки, полные core/GUI, `git describe`,
  версия CLI/GUI и SHA-256. GUI: `AMSignal-<версия>-x64.exe`, без начального `v`.
- `package_release.ps1 -OutputDir <новый каталог в dist> -Zip`: GUI, CLI,
  запускатели, README и GPLv3 LICENSE. Проверь состав и хэши готового пакета.
- Для GitHub публикуются GUI EXE и `SHA256SUMS.txt` с хэшем этого EXE.
  Отдельные CLI EXE и ZIP готового комплекта не загружаются; архивы исходников
  GitHub остаются доступны автоматически. Локальный ZIP не является вложением выпуска.
- Сохраняй старые теги/пакеты. Коммит/тег не означает публикацию. Отправка
  и публикация выполняются в пределах запроса пользователя, новый тег — явно.
- При распространении сохраняются GPLv3, авторство и доступность исходников.
  `.github/SECURITY.md` задаёт приватный канал сообщений об уязвимостях.
- Word/PDF пользовательского руководства ведутся из `docs/manual/`; при их
  выпуске сверяй действия с GUI и визуально проверяй результат вёрстки.
