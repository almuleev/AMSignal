# v0.17.13

## Русский

Добавлено открытие выбранного участка временной записи до полной загрузки файла.

- На начальном экране появилась кнопка «Открыть участок…», а в меню «Файл» —
  команда «Открыть участок записи…». Оба входа используют один диалог.
- После выбора LVM/TXT/CSV пользователь задаёт начало и конец в секундах,
  затем нажимает «Загрузить». Отмена диалога не открывает новый документ.
- Окно задаётся по исходной нормализованной временной шкале записи. Документ
  содержит реальные отсчёты внутри окна, без обнуления времени и интерполяции;
  фактические границы показаны в заголовке. Нужно минимум два отсчёта и канал.
- Источник документа, график, FFT/FRF по умолчанию и экспорт ограничены
  фрагментом. Переход между RAM и дисковым чтением сохраняет его границы.
- Индекс фрагмента не записывается вместо полного индекса файла. Последующее
  обычное открытие возвращает полную запись; перетаскивание не меняет поведения.
- Обновлены быстрый старт RU/EN и контракт источника. Добавлена GUI-регрессия
  реальных значений, границ анализа, дискового режима и повторного полного открытия.

Ограничения: режим предназначен для временных записей, не готовых спектров.
Без индекса текст до участка читается последовательно; быстрый переход по
смещению не гарантируется. Фильтр начинает состояние с начала фрагмента,
поэтому его начальные значения могут отличаться от обработки полного файла.
Большие записи и длительный стресс в рамках этой задачи не проверялись.

Проверки: сборки GUI и CLI, полный набор ядра — 1413 проверок без ошибок,
GUI — 7319 проверок; `git diff --check` без ошибок. Тестовые EXE пересобраны.

Локальный тег исходников. Публикация GitHub Release и отправка в удалённый
репозиторий не выполнялись; ранее собранный EXE содержит обозначение dirty.

## English

Selected intervals of time recordings can now be opened before loading the full file.

- Added “Open interval…” on the start screen and “Open recording interval…”
  in the File menu, both using the same dialog.
- After selecting LVM/TXT/CSV, enter start and end times in seconds and click
  Load. Cancelling the dialog does not open a new document.
- Times use the recording's normalized source timeline. The document contains
  original samples within the window without interpolation or resetting time;
  its title shows actual sample bounds. At least two samples and a channel are required.
- The document source, graph, default FFT/FRF and export are bounded by the
  fragment. RAM-to-disk transitions preserve these bounds.
- Fragment discovery does not overwrite the full-file scan index. Subsequent
  ordinary opening restores the complete recording; drag and drop is unchanged.
- Updated both quick starts and the source contract. Added GUI regression checks
  for sample values, analysis bounds, disk reads and subsequent full-file opening.

Limitations: this mode supports time recordings, not stored spectra. Without an
index, preceding text is read sequentially; fast seeking is not guaranteed.
Filter state starts at the fragment beginning, so initial results can differ
from processing the complete recording. Large-file and prolonged stress testing
were not performed for this change.

Validation: GUI and CLI builds, the full core suite (1413 checks, no failures),
7319 GUI checks, and a clean `git diff --check`. Test executables were rebuilt.

Local source tag only. No GitHub Release publication or remote push was performed;
the previously built executable carries a dirty version label.
