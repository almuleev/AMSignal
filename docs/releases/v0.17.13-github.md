# v0.17.12 — адаптивное использование RAM / adaptive RAM use

## Русский

Auto больше не ограничивает удержание исходника фиксированной третью доступного
бюджета. Массивы растут по фактической потребности с проверкой свободных RAM/commit
перед расширением, учётом старого буфера в пике и отдельным резервом подготовки.
Исправлено ошибочное отбрасывание данных на блоке, которому не требуется рост.
Ручной бюджет сохраняет загрузочную долю и системную защиту.

Резервирование различает уже выделенные массивы и будущие выделения: свежий
снимок OS не вычитает резидентные кэши дважды. Счётчики освобождаются после
последнего владельца, включая отменённые задания. Отказ выделения при подготовке
обычной записи допускает продолжение через файловый источник.

Перед расчётом освобождаются необязательные кэши, затем исходники неактивных
и активного документов по необходимости. Перевод на диск не меняет численную
ревизию и не объявляет освобождёнными массивы, удерживаемые живым снимком.
Обратная загрузка целого исходника возможна при повторном открытии, что исключает
переключение RAM/диск на каждом пересечении порога.

FFT/АЧХ оценивают выбранное N по полному timeline или индексу, а не seed из двух
строк. Потоковый анализ разделяет владение RAM-источником и не перечитывает файл,
пока исходные массивы доступны. Подготовка АЧХ оставляет место рабочим массивам
оценивателя; численная методика FFT/H1/Direct не изменена.

Проверки: сборки CLI/GUI; 31 проверка бюджета, 171 ресурсов анализа и 296 АЧХ;
7302 GUI-утверждения. На записи ровно 10 000 000 000 байт (47 390 720 отсчётов,
8 каналов) проверены удержание в RAM, полный FFT, H1, повторный H1 и перевод
на файловый источник при бюджете 128 MiB. Частоты и амплитуды FFT выбранного
участка после перевода совпали точно. Проверка перехода повторена после
исправления стенда: первоначально он сравнивал внутренние контейнеры вместо
числовых значений разных способов хранения результата.

Одиночные наблюдения до присвоения тега: открытие 37,3 с, полный FFT 33,0 с,
H1 13,7 с, пик рабочего набора 11,6 GiB. Это не медианы и не доказательство
общего ускорения относительно другой версии. Длительного стресс-теста,
полного core-прогона и испытаний свыше 10 GB не было. Существующая проверочная
сборка имеет маркировку v0.17.11-dirty; тег относится к исходникам. Публикация,
отправка в remote и новый релизный комплект не выполнялись.

## English

Auto replaces the fixed one-third source-retention share with incremental RAM
admission. Growth checks current physical and commit headroom, accounts for the
old vector during reallocation, and reserves preparation workspace separately.
Blocks that need no growth no longer discard a capped resident candidate.
Manual mode retains its loading share and system safety constraints.

The ledger distinguishes allocated resident arrays from prospective allocations,
avoiding double subtraction after an OS snapshot. Shared buffers remain charged
until their final owner releases them, including cancelled jobs. Allocation
failure during ordinary source preparation can fall back to the file source.

Analysis first releases optional caches, then demotes inactive and active source
documents as needed. Demotion preserves the numerical revision and does not
claim memory still held by a live snapshot. Whole-source RAM retention resumes
on reopening, preventing repeated RAM/file oscillation at the budget threshold.

FFT/FRF estimate selected sample counts from the complete timeline or index
instead of the two-row seed. Streaming analysis shares resident source ownership
while it is available. FRF preparation leaves room for estimator workspace.
The numerical FFT/H1/Direct methodology is unchanged.

Validation: CLI/GUI builds; 31 budget, 171 analysis-resource and 296 FRF checks;
7302 GUI assertions. The exactly 10,000,000,000-byte recording contains 47,390,720
samples and eight channels. Checks covered RAM retention, full FFT, H1, repeated
H1, and file-source demotion at a 128 MiB budget. Selected FFT frequencies and
amplitudes matched exactly after demotion. The transition check was repeated
after fixing the harness to compare numerical values rather than storage-specific
containers. No product-code change was required for that harness correction.

Single pre-tag observations: opening 37.3 s, full FFT 33.0 s, H1 13.7 s, peak
working set 11.6 GiB. These are neither medians nor a general speedup comparison
against another version. No prolonged stress test, complete core run, or input
above 10 GB was used. The existing validation executable reports v0.17.11-dirty;
this is a source tag. No remote push, release publication or new release package.

This commit combines the complete GPU rollback with AMSig workspace and result
persistence. Normal calculations use the CPU without OpenCL discovery, GPU-plan
compilation, calibration runs or manual preparation.

- Removed the GPU adapter, FFT/FRF integration, GPU-specific staging,
  Auto/CPU/GPU controls, status commands and persisted backend selection.
  Old backend settings and GPU environment variables cannot enable GPU work.
- Removed GPU tests/options, OpenCL/VkFFT headers and libraries from active
  sources, build flags, Makefile, PowerShell and packaging. The GPU-specific

  The archive is excluded from builds and executable packages. Original tags
  and release binaries remain intact. The source commits and ZIP checksum

costs. Warm Direct calculations benefited from GPU execution on the tested

performance improvement is claimed for this change.

### AMSig workspace and optional results

- `[workspace]` restores Time/FFT/FRF mode, independent Signal/FFT viewports,
  annotation lock and the visible paused playhead position. Bounds are validated;
  the FFT viewport also survives asynchronous computation and mode re-entry.
- Project `plot_mode` follows the stored data type rather than the active view.
  Saving a time-domain project from FFT mode preserves original samples.
- FRF metadata explicitly records `hann_periodic`. Analysis bounds and filter

  not start computation. The combined binary payload is limited to 4 MiB
  before hexadecimal encoding; oversized results are omitted without truncating
  N/L, and a compact FRF can be retained independently of an oversized FFT.
- Restoration validates the schema/application version, numerical configuration,
  source window, array dimensions/values, checksum and memory admission.
  Missing, incompatible or malformed caches fall back to ordinary calculation
  without blocking project loading. Original samples remain authoritative.
- Legacy projects retain their default workspace. Cross-version cache reuse
  and persistence of arbitrarily large disk FFT results are not promised.

Before committing, full core (1405 checks) and the completed GUI suite
(7278 checks) passed. Four rollback FFT/FRF result hashes matched the v0.17.9

historical archive. Clean tagged builds, full tests, version metadata and
packaging are verified separately with local logs. Creating this commit and tag
does not push them or publish a GitHub Release. No 10/20 GB files are used.

Проект `.AMSig` сохраняет условия повторного расчёта АЧХ. Раньше после
повторного открытия приходилось заново назначать опоры, отклики и метод.
Теперь эти параметры восстанавливаются вместе с поддерживаемыми настройками.

### Изменения относительно v0.17.8-cpu.1

- Новая секция `[frf_settings]`: роли опор/откликов, H1/Direct, запрошенный L
  (включая Auto), удаление среднего, порог опоры и экранное сглаживание.
- Сохранение границ частотного диапазона и амплитудной шкалы АЧХ, ручного
  или автоматического масштаба. Существующий общий участок анализа,
  исходные данные, формулы, фильтры и настройки обработки не заменены.
- При экспорте подмножества каналов роли перенумеровываются относительно
  экспортированных столбцов. Ошибочные индексы, дубли и пересечение ролей
  не применяются. Некорректные параметры отклоняются в пределах проверки импорта.
- Метаданные проектов, табличного экспорта и CSV АЧХ содержат
  `application_version` и `exported_utc`. CSV АЧХ дополнительно сохраняет
  `segment_length_requested` и `display_smoothing_octaves`. Основные
  параметры фактического расчёта уже присутствовали и сохранены.
- Добавлен GUI-сценарий сохранения/открытия/пересчёта: несколько опор,
  выбранный участок, H1, Direct/Auto, сглаживание, границы отображения,
  подмножество каналов, невалидные роли и старые метаданные.
- Обновлены инструкции переноса окружения RU/EN и контракты метаданных.

### Унаследованные изменения и границы

Основа — коммит `d43a5ce`, тег `v0.17.8-cpu.1`: параллельный разбор
текстовых записей и распределение FRF-преобразований по парам сегмент/канал.
Этот коммит уже содержит поправку амплитуды опоры на чётной границе
Найквиста и её численные регрессии. Исправление не меняет формулу H;
оно не добавляется повторно этим коммитом. Порядок накопления спектров
и управление CPU-пулом новыми правками метаданных не меняются.

Старые проекты читаются, но отсутствовавшие настройки АЧХ нужно назначить
вручную. Переход в режим АЧХ запускает повторный расчёт; восстановление
кэша результата и последнего режима интерфейса не заявлено. Сглаживание
является настройкой отображения и не заменяет исходный комплексный H.
Паспорт экспорта не подтверждает калибровки, приёмку объекта или внедрение.

## English

AMSig projects now preserve FRF recalculation settings. Reopening a new
project restores reference/response roles, H1/Direct, requested segment
length including Auto, mean removal, reference threshold, display smoothing
and FRF view bounds. Existing source samples, shared analysis interval,
formulas, filters and processing settings remain supported.

### Changes since v0.17.8-cpu.1

- Added `[frf_settings]` serialization and restoration. Channel subsets use
  role indices remapped to exported columns. Invalid, duplicate or overlapping
  roles are rejected; imported parameters are validated.
- Project/tabular and FRF CSV metadata now include `application_version`
  and `exported_utc`. FRF CSV also includes `segment_length_requested` and
  `display_smoothing_octaves`, alongside existing actual calculation metadata.
- Added GUI roundtrip coverage for multiple references, selected intervals,
  H1, Direct/Auto, smoothing, view bounds, channel subsets, invalid roles
  and legacy metadata. Updated bilingual portability instructions and contracts.

### Inherited changes and limitations

Built on `d43a5ce` / `v0.17.8-cpu.1`, retaining parallel text parsing and
segment/channel FRF scheduling. The parent already contains the even-length
Nyquist reference-amplitude correction and numerical regressions; this commit
does not apply it again. The correction leaves the transfer-function formula
unchanged. New metadata code does not change CPU-pool scheduling or spectral
accumulation order.

Older projects remain readable but cannot recover settings absent from their
files. Enter FRF mode to recalculate; result-cache or last-mode restoration
is not claimed. Display smoothing is separate from raw complex H. Export
provenance does not establish sensor calibration or laboratory acceptance.

### Validation

CLI and GUI builds succeeded. Rebuilt full core suite: **1405 assertions,
zero failures**; rebuilt full GUI suite: **7193 assertions, zero failures**;
FRF subset: **296 assertions, zero failures**. The synthetic GUI roundtrip
preserves frequency grids, masks and L/K/N; valid complex H agrees within
`10^-12`. This tolerance does not describe physical measurement accuracy.
`git diff --check` passed. Successful runs were reused after documentation-only
edits; assertion counts do not denote independent scenarios.

No new performance/FAMOS benchmark, second-machine validation or laboratory
acceptance was performed. Historical measurements remain tied to their original
versions. This is a local annotated source tag, with no remote push, publication
or newly versioned executable package.
