# v0.17.11

## Русский

Откат GPU и сохранение рабочего состояния `.AMSig` объединены в одном коммите.
Обычные вычисления выполняются на CPU без обнаружения GPU, компиляции планов
OpenCL/VkFFT, калибровок и дополнительных действий пользователя.

### Полный откат GPU

- Удалены `gpu_fft.cpp/.hpp`, подключения и вызовы GPU в спектре и АЧХ,
  вспомогательные GPU-буферы и отдельная подготовка пакетов для GPU.
  CPU-подготовка и преобразования снова используют прежний общий путь.
- Из интерфейса исключены переключатели Auto/CPU/GPU и состояние GPU.
  Настройка `compute_backend` и GPU-переменные окружения больше не читаются;
  старые значения в пользовательских настройках не включают GPU.
- Удалены GPU-сценарии и селектор тестов, GPU-параметры стенда, включения
  OpenCL/VkFFT и Linux `-ldl`, добавленные для GPU, из Makefile/PowerShell.
- Удалены активные сторонние GPU-зависимости, notices и их включение в комплект.
  Действующие справочники описывают CPU-реализацию.
- Сохранены ускоренный параллельный парсер, CPU FFT/FRF, исправления амплитуды
  опоры на Найквисте, параметры проектов и паспорт экспорта из v0.17.9.
  Откат не возвращает медленный парсер v0.17.7.

Причина отката — стоимость создания планов и пробных CPU/GPU-прогонов в первом
расчёте. Повторные GPU-расчёты Direct давали выигрыш на проверенной RTX 3070,
но это не устраняло задержку первого вызова. Систематическое общее замедление
CPU не установлено. Нового универсального коэффициента ускорения не заявляется.

### Архив исследования

Полная реализация v0.17.10 с точками интеграции, тестами, OpenCL-Headers/VkFFT
и лицензиями сохранена в `docs/development/history/gpu-v0.17.10/source-v0.17.10.zip`.
Рядом находятся описание восстановления и протокол первичной проверки отката.
Архив не подключается к сборке и не включается в комплект EXE.

Исходный коммит: `45a26985c5e401a5a2e88a986c7756941bc24819`;
CPU-база: `025774bb90e0100e1dc4475fc62181096611098f`.
SHA-256 ZIP:
`b23852e8bba06a4d8fceb1200ac12ef6ad706e5abfaef11875b818c5bb44c459`.
Старые теги и выпускные EXE сохраняются. Наличие GPU в историческом ZIP или
теге v0.17.10 не означает его наличие в текущем исполняемом коде.

### Состояние проектов .AMSig

- Новая секция `[workspace]` сохраняет активный режим «Сигнал»/«Спектр»/«АЧХ»,
  независимые видимые диапазоны Signal и FFT, блокировку разметки, положение
  и видимость курсора воспроизведения. Курсор восстанавливается на паузе.
- Границы проверяются по полному источнику. Частотный вид восстанавливается
  также после фонового FFT; возврат в неизменённый FFT сохраняет выбранный
  пользователем viewport вместо безусловного сброса к Найквисту.
- `plot_mode` проекта описывает сохранённые данные. Проект исходного сигнала
  остаётся временным, даже если сохранён из режима FFT; он не становится
  импортированным спектром. Исходные отсчёты не заменяются амплитудами.
- Окно АЧХ явно записывается как `hann_periodic`. Границы участка анализа и
  частоты фильтра сохраняются с численной точностью, без округления для Edit.

### Необязательные готовые результаты

- `[analysis_cache]` может сохранять уже готовые FFT и комплексные результаты
  АЧХ с сетками, масками, спектром опоры и coherence. Сохранение не запускает
  вычисления; готовые подходящие результаты восстанавливаются при открытии.
- Общий бинарный объём ограничен 4 MiB до hex-кодирования. Результаты сверх
  лимита пропускаются целиком, без уменьшения N/L. Компактная АЧХ может
  сохраняться независимо от не поместившегося FFT.
- Проверяются схема/версия приложения, численные настройки и участок,
  размеры и допустимые значения массивов, контрольная сумма и RAM-допуск.
  Несовместимый, повреждённый или отсутствующий кэш не мешает открытию
  исходных данных и обычному пересчёту. Кэш не заменяет исходную запись.
- Старые проекты без новых секций открываются с прежними defaults.
  Не обещается перенос готовых результатов между версиями программы или
  сохранение любого большого дискового FFT. Hex-представление увеличивает
  размер текстовых метаданных относительно бинарного лимита.

### Проверки и границы

Перед фиксацией исходников успешно выполнены полный набор ядра (1405 проверок)
и итоговый GUI-набор с новыми проектами (7278 проверок). Четыре контрольных
FFT/АЧХ-сценария отката совпали с CPU-хэшами v0.17.9. Сценарии проектов включают
старые файлы, неверные значения, повреждённый/устаревший кэш, Signal/FFT/АЧХ,
фоновый FFT, формулы/фильтр и потоковое сохранение исходных отсчётов.
Проверки утверждений не являются количеством независимых сценариев.

Подготовка тега включает аудит именно содержимого Git-индекса/коммита:
исследовательский архив исключён из поиска активной GPU-реализации.
Чистая сборка помеченного коммита, полные тесты, версия и комплект проверяются
отдельно; первичные логи сохраняются в `.build`. Коммит/тег не означают
отправки в remote или публикации GitHub Release. Файлы 10/20 GB не используются.

## English

This commit combines the complete GPU rollback with AMSig workspace and result
persistence. Normal calculations use the CPU without OpenCL discovery, GPU-plan
compilation, calibration runs or manual preparation.

### GPU removal and preserved CPU behavior

- Removed the GPU adapter, FFT/FRF integration, GPU-specific staging,
  Auto/CPU/GPU controls, status commands and persisted backend selection.
  Old backend settings and GPU environment variables cannot enable GPU work.
- Removed GPU tests/options, OpenCL/VkFFT headers and libraries from active
  sources, build flags, Makefile, PowerShell and packaging. The GPU-specific
  Linux `-ldl` addition is removed. Current technical references describe CPU work.
- Retained the parallel CPU parser and FFT/FRF improvements, the Nyquist
  reference-amplitude correction, project settings and export provenance.
  The rollback does not restore the older v0.17.7 parser.
- Archived the complete v0.17.10 source, integration, tests, dependencies and
  licenses in `docs/development/history/gpu-v0.17.10/source-v0.17.10.zip`.
  The archive is excluded from builds and executable packages. Original tags
  and release binaries remain intact. The source commits and ZIP checksum
  are recorded in the Russian section and the archive README.

The rollback addresses first-call plan creation and repeated CPU/GPU calibration
costs. Warm Direct calculations benefited from GPU execution on the tested
RTX 3070; a general systematic CPU regression was not established. No universal
performance improvement is claimed for this change.

### AMSig workspace and optional results

- `[workspace]` restores Time/FFT/FRF mode, independent Signal/FFT viewports,
  annotation lock and the visible paused playhead position. Bounds are validated;
  the FFT viewport also survives asynchronous computation and mode re-entry.
- Project `plot_mode` follows the stored data type rather than the active view.
  Saving a time-domain project from FFT mode preserves original samples.
- FRF metadata explicitly records `hann_periodic`. Analysis bounds and filter
  frequencies retain numerical precision rather than Edit-field rounding.
- Optional `[analysis_cache]` stores completed FFT/FRF arrays, grids, masks,
  complex transfer functions, reference amplitudes and coherence. Saving does
  not start computation. The combined binary payload is limited to 4 MiB
  before hexadecimal encoding; oversized results are omitted without truncating
  N/L, and a compact FRF can be retained independently of an oversized FFT.
- Restoration validates the schema/application version, numerical configuration,
  source window, array dimensions/values, checksum and memory admission.
  Missing, incompatible or malformed caches fall back to ordinary calculation
  without blocking project loading. Original samples remain authoritative.
- Legacy projects retain their default workspace. Cross-version cache reuse
  and persistence of arbitrarily large disk FFT results are not promised.

Before committing, full core (1405 checks) and the completed GUI suite
(7278 checks) passed. Four rollback FFT/FRF result hashes matched the v0.17.9
CPU baseline. Project coverage includes legacy/invalid metadata, stale/corrupt
caches, asynchronous FFT, processing and streamed original-sample export.
Check counts are assertions rather than independent scenarios.

The staged/committed tree is audited for active GPU code, separately from the
historical archive. Clean tagged builds, full tests, version metadata and
packaging are verified separately with local logs. Creating this commit and tag
does not push them or publish a GitHub Release. No 10/20 GB files are used.
