# AMSignal v0.17.5 — 2026-10-16

## Русский

### Состав выпуска после v0.17.4

Выпуск устраняет конкуренцию ненужного фонового обзора Signal с чтением
исходника для FFT/АЧХ и корректно возобновляет незавершённый обзор при возврате.
Численные алгоритмы FFT/H1, исходные отсчёты, участок анализа и формат проекта
не меняются. Версия формируется штатными сборочными скриптами из git-тега.

### Приоритет анализа и сохранение состояния

- gui_commands::set_mode при переходе в FFT/FRF вызывает
  cancel_recording_overview до запуска анализа. Действуют прежние проверки
  допустимости режима и ранний выход при повторном выборе того же режима.
- Отмена кооперативная: выставляется флаг существующего OverviewWorker;
  ожидание, join/shutdown и новый пул потоков в UI не добавлены. Готовые
  index/view, исходник и рабочий поток сохраняются.
- Поздние результаты отменённого запроса отбрасываются существующей защитой
  поколений и отмены. Отмена также завершает относящийся к обзору Snap.
- Если отменён pending-запрос, requested_pixels сбрасывается в 0. Старый
  готовый view может совпадать по диапазону, но не соответствовать отменённой
  плотности или набору каналов; при возвращении в Signal уточнение запрашивается
  снова. Полностью готовый matching view без pending переиспользуется.
- Изменение не добавляет записей Undo, не меняет численную ревизию и не
  подменяет полные данные анализа агрегатами обзора.

### Причина задержки и контрольный результат

Узкий аудит чистых rc.3/v0.17.4 при Manual 64 MiB выявил конкурирующий разбор
одного текстового файла потоками обзора и FFT. Загрузка запрашивала обзор
для 1024 px, bitmap-стенд рисовал 1000 px. После первоначального ожидания пять
paint запускали уточнение, но не ждали его завершения. Более быстрая новая
отрисовка оставляла больше фонового чтения на момент старта FFT. Поэтому
прежние +52% не являются доказанной регрессией математического ядра FFT.
В проверенной паре собственно дисковый transform занимал 0.58/0.54 с.

Контроль реализации использовал настоящий set_mode в обеих сборках:
чистая v0.17.4 и исправленный рабочий код. На том же файле 58 185 676 байт,
N=337132, восемь каналов источника, FFT одного видимого канала, Manual 64 MiB,
с незавершённым обзором первый FFT изменился с 8.3187 до 1.9168 с (-77.0%),
новый повторный FFT — с 2.2120 до 1.9221 с. Во всех четырёх полных результатах
совпали N и fingerprint. Это отдельная контрольная пара, не медианы,
не универсальный процент и не измерение ускорения АЧХ.

## English

### Changes since v0.17.4

This release prevents an unnecessary background Signal overview from competing
with FFT/FRF source reads and correctly resumes an unfinished overview on return.
FFT/H1 algorithms, original samples, the analysis range and project format are
unchanged. Standard build scripts derive the executable version from the git tag.

### Analysis priority and retained state

- gui_commands::set_mode calls cancel_recording_overview before starting
  FFT/FRF. Existing mode validation and the same-mode early return remain.
- Cancellation uses the existing OverviewWorker flag. No UI wait, join/shutdown
  or additional thread pool is introduced. Ready index/view objects, the source
  and the reusable worker remain available.
- Existing cancellation/generation checks reject late results. The associated
  overview Snap is cancelled as well.
- Cancelling a pending request resets requested_pixels to zero. A retained old
  view may match the range without matching the cancelled density or channels;
  returning to Signal resubmits that refinement. A fully ready matching view
  without a pending request is reused.
- Cancellation adds no Undo entries, changes no numerical revision and never
  substitutes overview aggregates for complete analysis samples.

### Delay diagnosis and controlled result

A focused clean rc.3/v0.17.4 audit at Manual 64 MiB identified concurrent text
parsing by overview and FFT readers. Loading requested a 1024-pixel overview,
whereas the bitmap harness drew 1000 pixels. Five paints after the first wait
started refinement without awaiting completion. Faster newer rendering left
more background reading unfinished at FFT start. The earlier +52% therefore
does not establish a mathematical FFT regression. The measured disk transform
itself took 0.58/0.54 seconds in the profiled pair.

The implementation check used actual set_mode calls in both builds: clean
v0.17.4 and the fixed working code. With the same 58185676-byte input,
N=337132, eight source channels, one FFT channel, Manual 64 MiB and a pending
overview, first FFT time changed from 8.3187 to 1.9168 seconds (-77.0%);
a new repeated FFT changed from 2.2120 to 1.9221 seconds. All four complete
results matched in N and fingerprint. These are individual controlled runs,
not medians, a universal speedup or an FRF performance measurement.

### Validation

- Rebuilt core suite: 1357 checks, zero failures, covering parsing, FFT/FRF,
  budgets, disk FFT, sources, overviews, caches and active background cancellation.
- GUI suite: 8654 checks. Added coverage includes both analysis modes, late
  result rejection, retained index/view/source, complete FFT/FRF sample counts,
  numerical revision/Undo, return and density refinement. Cancellation before
  the first overview is published, restart through the same worker and reuse
  of a ready view after a round trip without pending work are also checked.
- Full analysis chains on the same input in Auto and Manual 64 MiB matched all
  28 complete FFT/H1 result groups against the frozen baseline: raw/processed,
  filtering, selected range and return to raw. The harness uses set_mode and
  normal filter/FRF settings invalidation.
- Standard full CLI/GUI builds passed before release finalization. After the
  tag is created, CLI/GUI builds and GUI regression run from a clean v0.17.5
  checkout; git describe, executable version resources and SHA-256 are checked.
- Additional validation logs: .build/analysis-priority-verification-20261016;
  numerical harnesses: X:\AMSignal-comparison\2026-10-16\fft64-rc3-v0174.
  Clean release protocol: X:\AMSignal-comparison\2026-10-16\release-v0.17.5.
  These local service artifacts are excluded from the commit/distribution.

### Documentation and limits

AGENTS.md, docs/ARCHITECTURE.md and CHANGELOG are updated. References to the
existing unified external comparison report and its methodology are retained.
It contains the broad rc.3/v0.17.2/v0.17.3 series, five completed 10 GB openings,
the focused rc.3/v0.17.4 audit and implementation control. Incomplete runs are
not presented as medians; no new broad v0.17.5 series was run.
The retained broad series comprises 46 API cases, 414 processes and 2484
calls, 27 GUI analysis processes, 54 navigation processes and five 10 GB
openings; all 92 numerical fingerprint groups matched. At the user's request,
the 10 GB series was shortened to a new-index run for each version and a
cached-index run for rc.3/v0.17.2. The interrupted v0.17.3 retry was excluded;
that series contains no full 10 GB numerical analysis.

The earlier peak RAM increase and other recorded performance differences are
not claimed fixed. No new physical 8 GiB PC or FAMOS tests were run. Current
testing covers inputs up to and including 10000000000 bytes; 20 GB testing was
not resumed. This is validation scope, not an artificial opening limit.
Logic/numerical checks do not replace a separate manual visual audit of every
window and state.

The commit and annotated tag are local. Older tags, executables and packages
are retained. Local executables are unsigned. Creating the tag neither pushes
changes to a server nor publishes a GitHub Release.
